# 一次动作完成双臂穿戴与相机标定

RGB-D GUI 新增 **双臂一体标定 · 穿戴＋相机（一次动作）**。原单独 IMU 双臂标定、视觉辅助穿戴标定、相机标定和历史恢复均保留。支持双臂四部位，也可选左/右单臂。手掌和躯干穿戴标定不包含在此流程。

## 使用

成功应用所选结果后，“一键切换双臂为陀螺＋加计＋RGB-D”按钮才开放。点击会先检查左右上臂和前臂四个部位的相机标定、姿态流及配对中立位；任何部位不能切换时全部保持原模式，并显示原因。不会启动X1；录制、其他标定或X1随动期间拒绝切换。仅应用部分结果时，须补齐其余部位的有效标定才能一键切换全部四部位。

主界面“穿戴标定参数…”与各穿戴窗口共用弱先验权重 λ，默认0.15，范围0～2。设为0完全关闭原IMU平举拟合中的手动映射弱先验，不关闭动作方向、重力假设或质量验收。大于0.3会提示先验可能过强。采集时冻结并保存本轮参数；计算后可调整权重并重新计算，不会自动改变已应用结果。选择视觉辅助算法时，λ仅影响原IMU对照，不影响视觉主拟合或相机纠偏拟合。

离线 `combined_calibration_analyze.py` 与 `visual_wearing_analyze.py` 支持 `--prior-weight 0`。未指定时使用 `camera_guide.json` 中的 `wearing_prior_weight`，旧录制缺少该字段时使用0.15。结果报告记录实际使用值。

1. 固定相机和绑带，设备分配正确，启动 Gemini 与三维观测。参与上臂/前臂选择“陀螺＋加计”。已学习的零偏继续沿用，不强制重复学习，不重置积分器。先停止 X1 随动和其他标定、录制。
2. 打开新窗口，选择范围及穿戴算法：默认“原 IMU 平举标定”，与已有双臂联合穿戴算法相同；也可选择“RGB-D 视觉辅助穿戴标定”。
3. 设置倒计时、动作准备和保持时间，点击开始。共同动作是：中立 → 前举 → 放下 → **斜前举** → 侧举 → 再前举 → **再斜前举** → 再侧举 → 回中立 → 自由验证 → 结束保护。双臂前举/侧举时肘腕伸直、躯干朝向保持稳定。斜前举从正前方向左右外侧分别展开约30–45°，抬高约45–70°；角度不必精确，重点让肩肘腕在图像中分开。不要为避遮挡转动躯干。默认开始倒计时5秒、每步准备4秒、动作静止保持4秒、中立位保持5秒、自由验证10秒。默认录制约88秒，另有开始倒计时，最后3秒剔除。
4. 自动分析完成后，表格分别展示四个部位的穿戴结果和相机结果。每项独立勾选，失败项禁用，不要求四部位全部通过。相机通过不是穿戴通过的替代；相机纠偏不会自动修复不正确的安装映射。
5. 可先看穿戴双模型回放；相机三路对比是观测一致性诊断，不是真值。视觉辅助穿戴“通过，但需人工复核”的结果须看回放并明确确认后才能应用。
6. 确认后应用所选结果：先穿戴映射及共同中立基准，再相机标定。使用事务预检及失败回退，不重建积分器，不自动选择融合算法或启动 X1。仅应用穿戴而未选择相机的部位，其旧相机标定会停用，避免误以为已应用本轮相机结果。
7. 在已应用相机结果的部位手动选择“陀螺＋加计＋RGB-D”，先检查人体模型，再决定是否启动 X1。

相机通过、穿戴失败时仍可单独应用相机，但需自行确认现有/手动穿戴映射正确；不应把它当作两类标定均已成功。

## 同一采集，独立求解

原 IMU 路线直接复用 `fit_guided_arm`：采用设备参考系的重力对齐姿态做拟合，仍保留自然下垂骨段竖直及规范前举/侧举先验。应用使用同一中立窗口的**原始**积分姿态，各算法中立基准同步保存，不把重力对齐后的矩阵误当作原始姿态。

视觉辅助路线复用现有 RGB-D 穿戴拟合与人工复核规则。相机路线独立拟合 $d_C\approx Q_s R_s b_s$，不要求先应用本轮穿戴映射，不依赖 GUI 旧映射是否正确。

新录制使用 `camera_pose_protocol=visible-oblique-v1`。相机拟合仅使用首次中立、斜前举、侧举的静止窗口（首0.5秒、末0.2秒不用于拟合），不使用过渡动作、正前举或重复动作。每个拟合窗口至少8帧同期可信方向；斜前举与侧举平均方向须相差至少20°，并保留原有非竖直观测数和拟合雅可比秩检查。再次斜前举、再次侧举、回中立作为独立复测；每个窗口至少8帧，方向误差中位数须小于12°、P90小于25°。保留置信度、深度支持、骨长、SO(3)、同步和重力参考检查。正前举被遮挡不会因此否决相机标定。

原IMU穿戴算法仍使用标准前举/侧举，不将斜前举套入90°先验。可选的旧视觉辅助穿戴算法仍使用前举/侧举，正面遮挡时仍可能失败；这种视角建议选择默认原IMU穿戴算法。相机独立标定窗口也新增同样斜前举及复测动作。旧录制没有协议字段时仍按旧的前举/侧举窗口拟合和验收；新协议缺少斜前举窗口时明确失败，不偷偷回退。

引导期间按部位显示当前静止窗口的可信同期视觉帧实时抽样计数及失效原因，重复画面不重复计数。该计数不是最终验收帧数：离线分析使用全部源帧，额外执行骨长一致性与误差检查。准备动作阶段不计入静止采样。原穿戴算法保留已有拟合和复测门限，前臂侧举及躯干移动仍有提示。

这些误差是 IMU 预测骨段方向与 RGB-D 表面关键点方向的差异，**不是 GT 精度**。相机静止复测失败仍可能来自视觉深度、姿态求解、动作或时间匹配，不能仅归因于用户动作。与旧流程把整段含重复动作一起拟合相比，新流程可能暴露更多独立复测问题，但不强行放宽门限。

斜前举解决的是标定动作的可见性，并不能让遮挡关节在运行中变得可观测。实际动作指向镜头、关键点被遮挡或骨段近竖直时仍暂停相机航向更新，由IMU保持连续运动，观测恢复后再纠偏。不用IMU推测的关键点替代独立视觉测量。

## 数据与安全

- 一次原始联合录制保存在 `recordings/日期-编号/`，包含 IMU、各姿态流、RGB-D、视觉及引导时间窗。该入口没有新增第二套相机/UDP 接收器。
- 分析位于 `recordings/analysis_combined/录制编号-随机码/`：`report.json` 是总报告，`wearing.json` 是穿戴结果，`camera/` 是相机结果和对比数据。不会修改原录制。
- 可独立离线分析完整已有引导录制：`python combined_calibration_analyze.py <录制目录> --output <原录制外的新目录> --wearing-method imu`；视觉辅助使用 `visual`。缺少同一会话的实时姿态或引导窗口时拒绝使用。
- 设备、积分、相机、视觉会话变化，或活动的 X1/录制都会阻止应用。采集期间视觉纠偏冻结，拟合只使用纯 IMU 基线；不把已融合姿态再用于拟合自己的纠偏。
- 两路分析独立保留失败信息。应用时可以只选穿戴、只选相机或两项都选；未通过项不能强行应用。
- 无新增依赖。原始 RGB-D 占用磁盘较大，长验证前确认可用空间；历史恢复功能保持原样。

## 删除本次原始录制

窗口底部“删除本次原始录制（释放磁盘空间）”默认禁用；本轮分析完成并生成报告后启用，**不要求先应用，全部未通过也可删除**。点击后确认完整目录路径，以后台方式永久删除该原始录制文件夹，不移动到回收站（回收站不会立即释放磁盘空间）。分析目录和内存结果保留，已应用的实时标定不受影响；尚未应用的合格结果仍可在本窗口应用。视觉穿戴需人工复核的结果应先完成回放确认。

删除后不能再进行原始回放或重新离线分析，对应按钮禁用。请先关闭该目录的人体及相机回放窗口，停止录制/预约或分析。只允许删除 `recordings` 下当前窗口本轮完成的一体标定原始目录，并核对录制身份；禁止删除上级目录、分析目录或符号链接。删除过程中暂不能开始新一轮或关闭程序。新一轮采集/重新计算会重置删除授权。永久删除不能从回收站恢复；删除错误可能留下部分文件，请阅读提示，不会因此重置实时标定。
