# 手机局域网夹爪输入实验

无需安装 App 或新增 Python 依赖，使用 Python 标准库 HTTP 服务。

```bash
cd /home/hzb/Work/WT901
python3 OptUSBProj-ubuntu/lan_gripper_demo.py
```

终端输出含随机会话令牌的两个链接：手机控制页和电脑观测页。手机连接电脑热点后，在浏览器打开完整手机链接，点击启用并拖动滑杆。0 表示打开，1 表示闭合；电脑页面显示经过限速的标量值及目标值。令牌每次启动更新，不应公开分享。

默认仅绑定热点 `10.42.0.1:8767`，不占用 IMU UDP 1399，可与人体 GUI 同时运行。如热点地址改变，使用 `--host 新地址`；端口可用 `--port` 指定。Ctrl+C 停止服务。

## 协议与边界

- 浏览器约每 80 ms 发起一次同源 HTTP JSON 请求，不允许堆叠请求；这是快速验证版，不是 WebSocket 或硬实时链路。
- 控制数据包含 version、client、seq、enabled、closure。服务端校验有限数值、0–1 范围、递增序号，并仅允许一个活跃控制端。
- 服务器使用自己的单调时间计算超时，不使用手机时间；超过 0.7 秒无命令则停用并保持最后开合量。后台/锁屏触发停用，回来必须重新启用。
- 输出变化限速 1.0/s，实际 dt 上限 0.1 秒，断线不会自动闭合或继续追赶目标。
- 页面夹爪是二维示意；默认只观测。勾选“发送至 RViz”并启用手机控制后，服务以 20 Hz 向本机 UDP 13991 发送夹爪数据，由 `x1_imu_live.py` 与双臂统一合并发布 `/joint_states`。**不发送电机指令**。
- 局域网 HTTP 没有加密；令牌与同源校验不是生产级认证。只在可信私人热点使用，勿开放公网端口。本页“停用”不是真机急停。

验收建议：手机拖动，电脑观察同步；锁屏后确认停用冻结；重新打开确认需要重新启用；第二手机不得抢占正在启用的控制端。

## RViz 操作

1. 重新启动网页服务，打开本次输出链接（手机若有旧页面，请刷新）。
2. 人体 GUI → X1 预览 → “启动 RViz 模型” → “启动 ROS 接收（手机夹爪可单独预览）”。测试夹爪无需标定四个臂段。
3. 手机选择右夹爪 57 或左夹爪 7，勾选“发送至 RViz”，再点击启用。切换夹爪或反向选项会停用控制，需重新启用。

手机使用短竖向滑杆：向上闭合，向下打开。“手机握持布局”可选右手（滑杆靠右）或左手（滑杆靠左），会记住本机浏览器选择；只镜像界面，不改变机器人目标夹爪或映射方向。切换布局时停用控制，需重新启用，避免调整握持时误操作。无需重启服务，刷新手机页面即可加载布局更新。
4. 可同时开启已有双臂随动；夹爪有新鲜输入时发布完整关节状态，持续刷新基座到夹爪的 TF 链。若双臂未开启或断流，则臂关节保持末次角度（未接收过则为零），不会外推运动，也不将其视作新鲜 IK 输入。夹爪断流时，双臂发布保留夹爪末次角度，不回零。

网页和 X1 GUI 显示 ROS 桥回报的接收目标、发布角度、数据新鲜度及订阅者数量。网页直接经本机 UDP 到 ROS 桥，**不经人体 GUI 转发**，GUI 仅查询状态。订阅者计数和发布计数不能证明 RViz 已绘制；应检查完整 TF 链。初版仅发布夹爪关节会使臂链 TF 过期，此问题已改为完整状态刷新。

映射默认 `q = 1-c` rad：0% 对应 1 rad 张开，100% 对应 0 rad 闭合。依据现有工具“张开”预设及 URDF 范围，最终请在 RViz 中核对方向；可勾选反向映射进行对比。ROS 桥额外按实际 dt 限速 1 rad/s，限制 dt ≤0.1 s；每个夹爪分别保持，未选中的夹爪不跟随。

如已有旧版本 ROS 桥，请停止重启。不要同时运行关节滑杆控制器，否则多个 `/joint_states` 发布者仍可能互相覆盖；本功能不解决外部发布者冲突。GUI“停止”会停止其拥有的 ROS 桥；关闭弹窗仅隐藏。独立启动 ROS 桥命令：

```bash
cd /home/hzb/Work/WT901/urdf-model
source /home/hzb/miniconda3/etc/profile.d/conda.sh
conda activate x1_ros2_py
source /opt/ros/lyrical/setup.bash
source install/setup.bash
python script_python/x1_imu_live.py
```
