# X1：两个求解后端与两种任务模式

本功能只发布 RViz 关节状态，不连接机器人硬件。环境和主程序启动方式不变。

## 界面操作

在人体主窗口打开“X1 双臂实时预览”：

- “求解后端”选择数值最小二乘或 PoE / 解析雅可比迭代。
- 不勾选“优先精确末端位姿”：模仿肘、腕动作，保持原来的目标与权重。
- 勾选：只追踪末端位置和世界系朝向，不要求肘点、肘角或腕关节角模仿人体。
- 运行时锁定选择，先停止再切换。关闭弹窗仍保持后台运行，与之前相同。

默认仍是最小二乘＋动作模仿。两种后端都支持两种任务，共四种组合。
完整位姿模式目前用于双臂同时预览，因此必须勾选左右手掌跟随，四个臂段已标定，另有两台在线且有一致中立参考的手背设备。
手背可用手动轴映射或合格穿戴标定。不自动使用前臂朝向冒充缺失的手掌姿态。

## 目标和末端定义

末端固定为 URDF 连杆 `L6 / R56` 坐标系，不是夹爪尖端。
位置继续使用已验收的肩部相对位移比例映射，保持中立位腕点对齐；不重新强制机器人骨长。
完整朝向使用人体手掌的完整模型姿态，包括上臂、前臂和手腕运动。
STL 模型与当前 URDF 基座按 +X 前、+Y 左、+Z 上对齐，与位置映射一致；固定转换矩阵 C 当前为单位阵：

`R_target = C @ R_human_hand @ C.T @ R_robot_hand_zero`

机器人零位姿态不能省略。长度比例只用于位置，不乘进旋转矩阵。
完整朝向不依赖 IK 已解出的前臂朝向，否则不同后端会收到不同目标。
动作模仿模式仍用手相对前臂姿态，以及既有腕部局部轴映射；两种任务不能混为一谈。
完整位姿模式不直接指定关节 5/55 的角度，所有六个关节共同求解。
如果今后改用工具中心点，必须补入明确的固定工具变换，不能仅更改显示名称。

## 数学和求解

PoE 参数从 URDF 自动提取，旋量排列采用 `[omega, v]`，长度为米、角度为弧度。
提供空间/体系 FK、空间/体系雅可比和中间关节点雅可比。
空间、体系 FK 与既有 URDF 连乘应一致；有限差分检验用于验证各任务解析导数。

两个新后端使用相同任务残差：

- 模仿：腕点位置、肘点位置、手相对前臂朝向，以及既有连续性、零位偏好和伸肘项。
- 完整位姿：`e = log(inv(T_current) @ T_target)` 的六维误差，只含末端任务。角度分量权重 0.30，平移分量权重 5.0；两种后端相同。平移分量是 SE(3) 对数坐标，并非简单世界系位置差。

最小二乘用 SciPy 的数值差分雅可比。默认模仿路径保留原 `fit_arm` 调用以维持兼容。
显式雅可比路径对残差计算解析导数，包含 SO(3)/SE(3) 对数微分，而非直接将几何雅可比当作任意误差的导数。
每次迭代通过阻尼 0.01 的有界线性最小二乘求增量，并回溯检查残差下降。
每帧最多 20 次外层迭代，雅可比求解在完整迭代结束后检查 20 ms 时间预算（不是硬实时保证）。

两者使用同样的关节边界：预览边界与 URDF 边界取交集；腕长轴 ±90°，侧偏 ±45°。
整个 tick 的关节增量限制为 `min(9°, 120°/s * 实际 dt)`，不是每个内部迭代都允许移动这么多。
前一帧热启动；不可达目标、奇异位形和限位不会因改用 PoE 消失。

## 状态与安全

“求解成功”意味着获得有效、局部收敛或改善的跟踪步，不代表目标已精确到达。
完整位姿模式的位置误差大于 0.5 cm 或朝向误差大于 2°时，显示“目标尚未达到”。这只是显示阈值，不是真机精度保证。
不再以旧模仿路径的 8 cm 误差门槛拒绝完整位姿的所有改善步，否则较远目标可能一直无法开始移动。
模仿模式保留旧门槛。所有输出仍受速度、单步与关节范围限制。
短时臂段断流保持该侧；完整位姿模式手背短时断流也保持该侧整臂，持续超过约 1 秒停止预览。
模仿模式手背断流时保留原来的腕部保持、臂段位置继续随动行为。
没有碰撞、实机反馈或急停；不得将预览链路接入真机执行接口。

## 记录与同输入对比

新诊断格式为 `x1-live-diagnostic-v2`。除了原有数据，还记录模式、后端、求解耗时、迭代数、触限、世界朝向误差和完整任务目标矩阵。
启用两侧手掌，即使在默认模仿模式录制，也会记录两个模式需要的共同目标。
保存到 `recordings/x1_live/<时间戳-编号>/`。

可以对同一份有效输入依次求解四种组合，无需四次重新佩戴和录制：

```bash
conda run --no-capture-output -n OptUSBProj python -u OptUSBProj-ubuntu/x1_compare_ik.py \
  OptUSBProj-ubuntu/recordings/x1_live/<新录制目录> \
  --output OptUSBProj-ubuntu/recordings/x1_live/<新的对比输出目录>
```

输出四份 CSV 和 `summary.json`，分别统计位置、朝向、肘点误差、耗时、关节速度、触限及拒绝帧。
输出目录必须不存在，避免覆盖原记录。旧 v1 记录不含共同完整位姿目标，程序会明确拒绝，不猜测补全。
对比检查 URDF 指纹一致；四组使用相同有效帧、原录制 dt、零位初始关节角和相同限速。
无效帧均保持上一结果，不做不同的插值。比较程序不启动 ROS，也不发送控制指令。
耗时包含当前机器上的求解开销，受系统负载影响；建议重复跑几次再作性能结论。

末端更准确但肘姿不像人体，是取消肘模仿后的正常可能结果。
比较时先看同任务下两个后端的差异，再看改变任务目标的影响，避免混淆。
