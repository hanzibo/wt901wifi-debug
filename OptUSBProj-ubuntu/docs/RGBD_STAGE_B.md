# 阶段 B：二维识别＋相机真实深度

当前实现独立的上半身三维观测，不纠正 IMU，不改变 STL 人体或 X1 随动算法。RTMW3D 仅提供还原到原始彩色图像的二维像素与分数，其预测三维坐标全部丢弃。

## 启动与界面

关闭旧的采集窗口以释放相机和 UDP 1399，再双击桌面 **WT901-RGBD联合采集**。勾选「三维观测：RTMW二维＋真实深度（不纠偏）」，点击「三维 / 可靠性详情」。或直接执行：

```bash
cd /home/hzb/Work/WT901
conda run --no-capture-output -n OptUSBProj-fusion python -u OptUSBProj-ubuntu/fusion_run.py \
  --camera-source orbbec --rgbd-fps 10 --rgbd-warmup 2 --rgbd-pose
```

无需新增依赖或下载；使用已有缓存 YOLOX、RTMW3D ONNX 权重与 CUDA 后端。缺少权重或 GPU 运行库会明确报错，原始采集继续，不自动下载或悄悄回退 CPU。

彩色预览：绿色点/线是通过深度检查的观测；橙色点表示二维识别成功但深度检查拒绝。勾选深度预览时显示深度而非彩色覆盖线。诊断弹窗包含独立三维骨架、肩/肘/腕/髋八点的坐标、二维分数、深度支持比例、局部深度跨度、拒绝原因、骨段长度。拖动骨架可旋转，滚轮缩放。坐标单位米，光学系 X 向右、Y 向下、Z 向前；显示自动居中不等于移除了记录中的绝对相机位置。

点击「相机画面独立窗口 ↗」可将预览拖到另一台显示器，并自由调整大小/最大化，始终按原图比例显示。关闭该窗口、点击窗口内「返回主界面」或主界面返回按钮，画面会重新嵌入主界面。此操作只移动显示控件，不停止相机、推理或录制，也不创建第二条采集链路；普通摄像头、RGB-D 彩色/深度、关键点覆盖及回放均适用。

## 真实深度与质量门控

原始 RGB 像素先按彩色内参与畸变求归一化射线，再按配准深度的内参与畸变求取样像素。不能仅因两幅图尺寸相同就假设畸变相同。本机阶段 A 标定中彩色有畸变、配准深度标定畸变为零。每点取 7×7 邻域的有效深度中位数，沿彩色射线反投影：

$$
p_C=z\begin{bmatrix}x_n&y_n&1\end{bmatrix}^{\mathsf T}.
$$

默认门控是初版工程启发式，不是精度保证：

- 二维分数至少 0.5，像素不越界。
- 深度 0.25–6 m，邻域有效支持至少 50%，中心 3×3 至少三个有效点。
- 邻域 P90−P10 不超过 100 mm＋2% 深度；中心与邻域深度不能明显冲突。
- 双臂骨段/肩宽宽松范围 8–85 cm；肩肘腕同时有效时，前臂/上臂比例须在 0.35–1.8 范围，否则拒绝腕点；短间隔三维跳变限制为 0.18 m＋3 m/s×间隔。
- 初版要求只检测到一人；多人时拒绝，不自动切换追踪身份。

无效点记为 null，不保持旧点冒充有效点。超过一秒的实时结果标为过期，清空当前骨架。它们是衣物/皮肤**表面观测**，不是骨骼关节中心；即使二维置信度高、局部深度平滑，也可能取到背景或遮挡物。未来融合必须继续结合骨长、时间关联和多源一致性，不能把本门控当作遮挡已完全解决。

采集与 GPU 推理分开：推理队列只保留最新帧，忙时跳过待处理旧帧，避免积压；状态显示跳过数。原始 RGB-D 的录制不依赖推理完成。推理耗时不等于端到端延迟，状态另显示源帧年龄。

## 记录与回放

启用观测后正常使用联合录制按钮/定时录制。原文件保持阶段 A 格式，新增 `vision.jsonl`：每条结果有源帧接收时间、实际保存的 `frames/…jpg`、二维点、米制三维点、有效性、原因、深度像素、骨长、耗时。只记录能匹配到保存源帧的结果；末尾三秒同样截断。队列满、源帧缺失、截断计数保存在 manifest 中。关闭观测不结束原始录制。

```bash
conda run --no-capture-output -n OptUSBProj-fusion python -u OptUSBProj-ubuntu/fusion_run.py \
  --replay /绝对路径/录制目录
```

包含视觉结果的录制可直接回放三维诊断，不需要相机/UDP/GPU 推理。回放按源帧时间展示，不是在模拟当时的推理延迟。时间仍是阶段 A 的主机接收时钟，没有完成相机曝光与各 IMU 内部时钟的物理同步标定。

已有阶段 A 录制可独立分析，不改写原录制：

```bash
conda run --no-capture-output -n OptUSBProj-fusion python -u OptUSBProj-ubuntu/rgbd_analyze.py \
  /绝对路径/原始录制 --output /绝对路径/新的分析目录 --every 1
```

输出目录必须不存在。生成 results.jsonl、report.json、前五帧覆盖图；这是一份独立分析，不是完整联合回放目录。可用 `--max-frames 20` 做快速检查。

## 验证与用户下一次采集

已用已有真实 RGB-D 录制抽样 20 帧通过本地 CUDA 分析，推理中位约 37 ms；当时仅坐姿部分上身入镜，不能证明完整上半身动作精度。自动测试覆盖反投影、畸变坐标转换、空洞、前背景混合、低置信度、跳变、多人数拒绝、丢弃网络预测 Z、精确源帧关联、回放和末尾截断。

请将相机调整到肩、肘、腕、髋都在画面内，先保持中立，然后慢做前举、侧举、屈肘、转身和手臂朝镜头。录制约 30–60 秒。先核对橙色点、骨段长度与遮挡恢复，不急着开启纠偏。下一阶段再做相机到人体参考系标定，以及可信视觉低频纠航向；目前尚未实现该融合。
