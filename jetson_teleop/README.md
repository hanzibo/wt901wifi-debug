# Jetson 轻量真机遥操作

本目录是独立入口，不替换 PC 程序。姿态积分、重力纠倾斜、手动轴映射、同源 IK、
轨迹规划、断流保护、停止手势和回位仍复用原项目代码。因此必须保留完整 Git 仓库，
不能只复制此目录。没有 RGB-D、穿戴标定、CoppeliaSim、VTK、ROS 或手指控制。
人体预览是固定骨长骨架，机器人预览是发送指令的 FK，不是真机反馈或碰撞检测。
没有外部航向校正，长期航偏仍会累积。

## 安装与运行

已验证目标：Ubuntu 20.04 / aarch64 / L4T 35.4.1。
保留系统 Python 3.8，使用 uv 安装 Python 3.11；不要替换 `/usr/bin/python3`。
仓库根目录下的 `.venv` 为本板专用，不提交或从 PC 复制。

### 批量切换 IMU 接收端

板子桌面 IMU 管理窗口新增“批量迁移在线 IMU 到电脑热点 / 其他接收端…”；
电脑手腕程序的“热点设备 / 在线 WT 设备”窗口新增“批量迁移在线 IMU…”。
两个入口使用同一窗口及协议，可从当前 STA 网络直接修改，不必先逐台恢复 AP。

预设为开发板 `HUAWEI-509 → 192.168.3.8:1399` 和电脑热点
`WT901-LAN → 10.42.0.1:1399`，SSID、地址和端口均可编辑。预设地址不会自动跟随 DHCP；
请核对目标接收端当前地址，密码在本次窗口输入，不写入预设文件或日志。

使用前制动并断开真机串口，开启目标网络及接收程序。选择预设、输入并确认密码，
勾选需要迁移的设备（刷新后默认全选），勾选就绪确认，再确认一次即可逐台发送。
固定本次设备清单，每台发送前重新验证在线 ID/IP；150 ms 间隔，不自动重试。
可随时停止后续发送，已发送的配置不能撤回。板子串口、IK、自动启动或回位运行时禁止发送。

从电脑热点迁出时，整批发送完毕前不要关闭热点；迁回电脑前，先开启电脑热点。
窗口只显示“已发送”，UDP 没有确认回执，原端断流不等于切换成功，
必须在目标接收端逐台核对 ID 的实时数据。错误密码或目标地址可能需要恢复 AP 后重新配置。

### CPU IK 加速与只读诊断录制

板子专用依赖增加 `numba==0.61.2`（由 uv 安装到本板 `.venv`）。
启动界面前预热 JIT；首次可能多等约十余秒，缓存后会缩短。
同源 IK 仍使用原 SciPy 分阶段优化、SO(3) 旋转对数和数值差分。
只把 PoE 运动链与位置/正则残差编译为 float64 CPU 内核；不用 GPU、fastmath 或 float32。
PC 原程序默认不启用该后端。编译或启动自检失败会阻止启动，不静默改用另一套算法。
原有限位、速度/加速度限制及 250+250 ms 断流保护不变。

主窗口底部新增“开始录制 IK / 收包诊断（不启动真机）”与录制秒数（默认60秒）。
先按原流程归零臂段与手背，然后点击录制并做实际动作；**可以完全不连接机器人**。
再次点击停止，或等待定时结束。界面显示文件路径：
`recordings/jetson_ik/<时间-随机后缀>/diagnostic.jsonl`。
录制复用已有 UDP 接收器，不开第二个端口、不发送设备命令、不赋予输出许可。
内容包括 IMU 解析值/收包与内核时序、约50 Hz姿态快照、配置与场景几何。
若正在控制，还记录实际 IK 求解、过期丢弃及目标提交耗时。
未连接机器人时没有“真实控制 IK 耗时”，但可以离线回放姿态测量。
写盘在独立线程，队列有界；丢弃或写盘失败会显示“记录不完整”，不改变控制保护。
录制时请保持所选模式、checkpoint、掌向设置不变；需要更改时请分段录制。

离线工具不会连接 UDP 或串口，也不会发送机器人指令：

```bash
.venv/bin/python -m jetson_teleop.benchmark_ik --frames 40 --profile
.venv/bin/python -m jetson_teleop.replay_ik recordings/jetson_ik/<目录>/diagnostic.jsonl --max-frames 300
```

回放使用录制时的场景几何、限位、方向和掌向设置，对比原后端与编译后端。
两套求解器均从中立初值开始，最多取前300个有效快照；不重建录制前的求解器历史。
报告中位、95分位、最大耗时及两套结果的最大关节差异。
这是离线计算基准，不是按真实时序运行的闭环测试，也不证明真机机械安全。

### 在线分段计时与四组负载对照

板端同源IK额外记录每侧及总求解的 `wall_ms`、`thread_cpu_ms`；
`ik_solved` 和控制日志的 `timing` 还含输入读取、求解后校验及提交时序。
线程CPU时间不包含未获调度的时间，但墙钟与CPU之差不能单独证明是GIL竞争。
计时不改变求解结果、输入原始期限或250+250ms保护。

使用包含实时 `ik_begin` 的动作录制及**同一次控制日志**，运行无串口对照：

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m jetson_teleop.benchmark_pipeline \
  recordings/jetson_ik/<目录>/diagnostic.jsonl \
  --control OptUSBProj-ubuntu/recordings/real_robot_imu/<目录>/control.jsonl \
  --repeats 2
```

四组依次为IK、加录制IMU姿态处理、再加离屏Qt界面、再加诊断JSONL记录。
第二轮反序运行，减小固定测试顺序的影响。每组采用相同首次控制指令初值、
相同IK输入序列和录制时序；记录每次左右臂墙钟/CPU、开始延迟及CPU频率快照。
默认最多200帧，可用 `--max-frames 1..500`、`--stages ik pose gui logging` 选择。
JSON结果输出到stdout，进度输出到stderr。录制不完整时报告会明确标注。

工具使用解码后的文件数据，强制禁止Python串口和socket打开，所有界面操作禁用；
不占用1399，不发送设备指令。比较时保留所有固定输入，若落后则报告排程延迟，
**这不是生产控制的旧输入排队策略**。
IMU滤波器从文件前段初始化并复用记录的中立矩阵，但不重建录制前的全部学习历史。
这四组不包含UDP内核/解码、真实屏幕合成、串口轨迹规划或厂商伺服执行负载，
因此不能仅凭结果保证真机连续运行；若仍有未解释差异，须继续隔离规划器负载。

### 独立 IK 进程（板端默认）

ARM 入口左右臂六轴默认勾选（仅双臂模式可输出右臂），仍可手动取消；
加载 checkpoint 不会重新勾选用户已取消的轴。连接并确认上电起点、加载预设后，
可直接点击“倒计时锁定目标”：若已启用停止信号且参考未确认，会先弹出参考角确认，
再弹出原有运动安全二次确认。接受安全弹窗后才授予本次安全许可，无需额外勾选安全框。
取消任一弹窗不会启动；设备归零、输入新鲜度、检测轴许可与范围检查仍须满足。
该便利流程仅 ARM 入口启用，PC 原入口仍要求先勾选安全确认。

板端正式入口的单/双臂同源 IK 使用 `spawn` 子进程。初始接管前在后台创建、
预热并求解；完成后仍重新检查输入、参考、路径许可，再进入原来的平滑过渡。
子进程只接收运动学几何、限位、人体目标及上一解，不接收 Qt、UDP 或串口对象。
子进程还禁止打开 socket 和机器人 tty 设备，不会自动重启或退回另一后端。

PoseService 继续处理有效 IMU 数据的积分与重力纠倾斜。LiveIK 每次求解结束后
从该服务读取最新完整姿态；管道最多有一个未完成请求，不积压历史目标。
“最新”策略不用于丢弃原始角速度积分数据，也不会反复取消每个正在计算的目标。
结果仍使用原输入期限，停止或参考变化后的旧结果被丢弃，250+250ms保护不变。
停止、异常、取消启动及退出会回收 IK 子进程。真机无关节反馈这一限制不变。

诊断元数据的 `backend` 为 `spawn_process_numba_geometry`。
`solver_timing` 含子进程计算墙钟、CPU、每侧时间和管道往返 `roundtrip_ms`；
`ik_thread_cpu_ms` 为子进程计算CPU，代理线程CPU另存 `ik_proxy_thread_cpu_ms`。
外层 `ik_ms` 包含请求往返和父进程开销，不能只看子进程内核时间。

相同输入的线程/进程对照（仍不连接设备）：

```bash
QT_QPA_PLATFORM=offscreen .venv/bin/python -m jetson_teleop.benchmark_pipeline \
  recordings/jetson_ik/<目录>/diagnostic.jsonl \
  --control OptUSBProj-ubuntu/recordings/real_robot_imu/<目录>/control.jsonl \
  --stages ik logging --backends thread process --repeats 2
```

对照为保留全部输入的数值实验，不代表生产队列；最新版本替换和过期拒绝由单独
回归测试覆盖。板端实测完整负载的中位往返约33ms，P95约42ms，具体见 VALIDATION.md。
首次启动预热另计，不能据离线结果宣称真机已不再超时。

实测时安全退出旧窗口，重新打开原桌面入口。控制窗口标题应包含“独立进程 IK”。
按原流程归零、加载预设，先开始60秒诊断录制，再人工授权接管。
记录应覆盖过渡、随动和人工停止；出现gap或超时后保留原记录，不自动重启恢复。

也可运行 `bash jetson_teleop/launch.sh`。本目录附带 `WT901-Jetson.desktop`，
其中路径针对当前板子用户 `mic-711on`；更换用户/仓库位置时须修改，不用于 PC 启动。

## 独立 IMU 接入与管理

桌面入口 `WT901-Jetson-IMU.desktop` 或 `bash jetson_teleop/launch.sh --imu-only`
只打开管理窗口，显示板子所有网卡 IPv4、实际监听端口、在线 / 离线设备 ID、分配部位、
设备发送端点、两秒平均收包 Hz、距末包 ms、电量估计和 RSSI。不启动机器人输出。
两种桌面入口使用仅同用户可访问的本地 IPC，只负责打开窗口，不传递启动或运动指令；
管理与控制始终共用一个进程里的单个 UDP 1399 socket。重复点击不会新增接收者或抢包。
若已运行，第二次指定的配置路径不会重新加载；更换运行配置须安全退出后重启。
关闭控制主窗口但保留管理窗口时，会先按原逻辑制动、关闭串口，然后继续收包。

PC 辅助配置步骤：

1. 原电脑热点下找到在线 IMU，确认没有真机输出后切回 AP/UDP；然后 PC 连接该设备 AP。
2. 重启 PC 手腕程序以加载新版，进入“接入新设备”，选择
   **外部 Wi-Fi / 路由器（其他设备 / Jetson 接收）**。
3. 填路由器 SSID（如 `HUAWEI-509`）及密码，UDP 目标填板子有线 IPv4
   （当前 `192.168.3.8`），端口 `1399`；不要使用当前 `bjut_wifi` 的自动地址或路由器 `.1`。
4. 确认写入后，在板子的 IMU 管理窗口验证设备 ID、Hz 和距末包时间。
   PC 显示“配置已发送，远端未验证”，不会因为自己未收到数据而误报失败或接入成功。
5. 多台设备逐一重复；板子 / PC DHCP 地址变化后须重新核对接收目标。

管理窗口的“将选中的在线 IMU 切回 AP / UDP”仅操作选中设备，默认确认选项为“否”。
任何真机串口连接（即使暂停）、IK / 启动 / 回位期间都不允许执行；确认后再次核对状态和
设备新鲜度，再复用原 `GuiUdpSource.switch_to_ap_udp`。UDP 没有设备确认回执，
收包消失也不能证明成功，必须到 PC 的 Wi-Fi 列表验证对应 ID 热点；失败时按设备说明恢复 AP。

Qt 只安装 PySide6-Essentials（Core/Gui/Widgets），无需 Addons。
实际 X11 桌面还需 Ubuntu 的 `libxcb-cursor0`（离屏测试不会检查此依赖）。
有管理员权限时安装该系统包；无管理员权限时，可把官方 arm64 deb 解包到
`jetson_teleop/.runtime/`，`launch.sh` 会仅为本程序加载其中的运行库。
Ruckig 0.19.4 在 ARM 上需要源码编译（CMake ≥3.15、C++ 编译器和 Ninja）；
该板已有的 GCC 9 / CMake 3.16 已满足构建要求，不可擅自换规划算法。
部署时可临时设置 `http_proxy` / `https_proxy`，不改系统网络配置。
`--probe` 只接收并统计 UDP，不加载 Qt、不打开串口；与其他程序同时占用 1399 会失败。
`--self-test` 只离线检查 IK、轨迹和零手指协议帧。

## 每机配置（不进 Git）

`runtime.local.json` 保存六个设备 ID、六套轴映射、发送 Hz、左右各六个协议方向、
掌向局部偏置轴/角，以及左臂和双臂的默认 checkpoint 路径。
可在 PC 使用 `prepare_config.py --left <JSON> --bilateral <JSON>` 打印配置草稿，
再明确保存为 `runtime.local.json`。它默认 20 Hz、方向均 +1、掌向 Z +90°；
这与近期运行记录一致，但更换机器人/穿戴方式后必须重新核对，不能当机械标定。
`checkpoints/` 保存单独通过 SSH/SCP 传来的个人预设；两个目录都被 Git 忽略。
加载 checkpoint 仍不恢复启动许可、归零参考、停止姿态确认或自动启动。
手动映射必须启用；不接受依赖穿戴标定的预设。

控制面板的 Checkpoint 窗口也使用本目录的 `checkpoints/`；启动默认预设以
`runtime.local.json` 指定的文件为准。不修改 PC 的预设目录。

## 首次验证顺序

1. 不连接机器人串口，先 `--self-test` 和 `--probe 10`。IMU 目标地址须是板子的
   有线 IP（当前 `192.168.3.8:1399`），不是 PC 的 `.7`。探测程序不改设备配置。
2. 板子本地桌面启动 GUI，核对设备部位、轴映射、协议方向与掌向偏置，分组采集中立参考。
   先点击上臂 / 前臂采集，在倒计时结束前自然下垂；再让手背处于所需中立姿态，单独点击
   手背采集。两组倒计时独立设置，默认均为 3 秒，可设 0–60 秒，可取消。
   左臂模式采集左侧 2 个臂段与 1 个手背，双臂模式采集 4 个臂段与 2 个手背。
   每组只改本组参考；与 PC 原程序一致，倒计时结束时仅采集最近 2 秒在线且已有姿态的设备，
   离线或无姿态设备跳过并显示完成数量。两组所有设备均完成才允许连接串口。
   重新采集任一组会暂时撤销连接许可；更换模式或取消配置核对会清除两组完成标记。
   主窗口可直接选择“仅左臂 / 双臂”，与控制面板同步；按钮标明本次采集设备数，
   状态栏分别显示臂段 / 手背完成数量。仅左臂模式不会更新右侧中立参考。
   骨架默认非镜像正视图，人体左侧显示在画面右侧；蓝色和“左 L”表示左侧，
   橙色和“右 R”表示右侧。“镜像预览”只改变画面，不改变设备分配、IK 或串口输出。
   每台设备显示重力参考、零偏初始化和当前静止状态；本模式就绪数量只统计新鲜数据。
   初始化需满足原算法静止门槛（加速度模长接近 1g、低角速度、加速度方向变化小），
   重力参考约需连续静止 0.3 秒，首次零偏学习约需 0.8 秒；这些不是独立墙钟倒计时。
   学习状态仅作提示，不拦截中立位采集，也不再对采集额外作严格静止判定；
   请仍在倒计时结束时保持所需中立姿态。此调整不改变真机跟随时的断流保护。
   就绪后重力纠倾斜与静止零偏更新继续运行；中立位采集不会重置滤波器学习。
3. 真机重新上电并人工确认全部关节 90°、手指量 0；选择串口，连接本身不发送角度帧。
4. 核对 Checkpoint、仅勾选需要的输出轴，确认独立断电手段、安全空间后，沿用原启动流程。
   先单臂小幅测试，再双臂；延时锁定与自动跟随仍需要二次确认。
   自动接管遇到短暂输入 / IK 中断时，沿用写线程的限时减速等待，不立即取消；
   恢复有效新解后继续，若发生在过渡后的等待阶段则重新等待完整的设定时间。
   等待期间不允许发起自动跟随；硬超时、故障、人工暂停仍取消且不自动重试。
5. 停止手势、手动暂停、顺序回位沿用原方案；断流超过保护期限后锁停，不自动恢复。

本软件无位置反馈，安全确认和“到位”都不是编码器实测。退出会请求原控制线程制动、
关闭串口后再退出，但软件暂停/制动不等于独立急停。此次自动化部署不执行真实运动测试。

## 板端调度与诊断

初始单臂 / 双臂 IK 在后台计算，期间不发送运动指令。计算完成后再次检查当前新鲜输入、
参考、配置与授权，再进入原平滑过渡流程；取消或配置改变后的迟到结果会丢弃。
倒计时自动接管也经过该后台阶段，不绕过二次确认和原启动门槛。
第二批调优将唯一的 UDP socket 和 PoseEngine 交由独立后台线程持有，持续收包并处理全部
有序角速度数据，约每 20 ms 发布姿态快照。窗口仅约每 100 ms 读取脱离后台的显示副本，
中立位采集和切回 AP 也经后台命令队列执行，不并发修改积分器或重复绑定端口。
连续 IK 使用最新快照，完成后直接交给唯一串口规划线程，不再等待 Qt 界面回调。
提交前后都检查输入原有效期、参考代次和控制会话；输入不会因为求解完成而获得新的有效期。
过渡期人体偏移检查另由采集后台执行，不依赖 IK 完成或界面刷新。暂停 / 停止手势 / 硬超时
撤销本次会话，迟到结果不能重新恢复输出；手动跟随确认和自动接管的二次确认仍保留。
自动接管的状态通知只用于唤醒界面：流程重新读取串口线程的实时输入保护快照，使用同一个
硬截止时间，不再用界面收到 gap 通知的时刻重复计时。短暂恢复即使没有落到一次状态显示中，
也通过 gap 代次变化重置完整的稳定等待时间；真正超时、人工暂停及会话更换仍撤销授权。

板端日志保留全部事件，普通遥测批量刷新间隔为 0.1 秒，关键故障 / 启动事件立即刷新；
关闭时排空。PC 默认仍逐条刷新。日志新增 `initial_ik_started/finished`，并记录
`acquisition.source_event=pose_service_summary`（10 Hz 计数摘要），采集详细事件保存在最多
2000 条的内存环形缓冲。
后台故障或会话结束时尝试导出 `acquisition_trace`，包含覆盖计数；它只是故障前的局部窗口，
并非完整逐包记录。`arm_ik` 的 `timing.backend=true` 和 `backend_delivery_ms` 标记后台直接交付，
结合 `arm_target_received` 的锁等待 / 更新间隔可定位求解和串口交付耗时。
PC 仍保留原来的 GUI 交付和逐包诊断路径；板端测试的 `background=False` 仅用于旧路径回归。
本轮不改变 IK 数学模型、运动限制、250 ms 输入新鲜度或额外 250 ms 减速等待保护。
自动化测试仅使用合成 UDP 和虚拟串口；双臂实时表现仍需实际运行后的板端日志确认。

## 私有仓库同步

代码在 PC 开发、提交并推送。当前板子没有 GitHub 凭据，因此首次部署使用
`git bundle` 经 SSH 同步同一提交，没有复制 GitHub 凭据或临时公开仓库。
后续可继续增量 bundle，或另行配置板子的只读部署密钥后使用普通 `git pull --ff-only`。
个人 checkpoint 与运行配置始终通过 SCP 单独复制，覆盖已有配置前应先备份。
