# 阶段 2：融合协调拆分与手动验收

## 1. 范围与边界

阶段 1 已由用户手动验收通过，提交为 `c55f392`。
本阶段只拆职责，不改融合数学、标定判据、人物跟踪算法、IK 或发送参数。

`fusion_gui.py` 从 1492 行降至 1173 行，提取了 24 个方法：

| 模块 | 职责 |
| --- | --- |
| `fusion_camera_controller.py` | 相机/推理线程启动、停止、退出与错误处理 |
| `fusion_vision_controller.py` | 切换资格、人物选择、原标定者恢复、在线换模型 |
| `fusion_calibration_controller.py` | 相机报告验证与应用、穿戴报告应用/撤销 |
| `fusion_recording_controller.py` | 手动/定时联合录制、取消预约、元数据快照、结束与事件裁剪 |
| `fusion_gui.py` | 控件装配、显示/渲染、轮询、窗口关闭流程及兼容入口 |

协调器不导入 Qt、融合窗口或标定窗口。线程工厂、录制器、提示回调和时钟可以注入。
但它们**仍依赖窗口提供的状态与控件接口**，不是彻底独立的领域层。
现阶段刻意不再建立第二份状态：`session`、`pose_worker`、`vision_epoch`、
`live_fusion` 等仍由窗口持有，避免现有标定窗口读取旧值。
原方法签名和入口保持；窗口只转发到协调器。
大块 UI 装配、渲染和轮询仍待后续阶段处理，不宣称巨型窗口已经完全消除。

锁住的行为包括：

- 短暂遮挡或多人干扰不等于相机移动；仍按原质量门控暂停/恢复。
- 主动换人物仍停用原相机标定；必须明确确认原标定者才能走恢复路径。
- 换模型保留补偿角；确认原标定者后仍需短时方向一致性检查。
- 相机重启/采集会话改变不能走原人物确认捷径。
- 录制/标定分析期间不能换模型；未就绪的 RGB-D 不创建录制。
- 手动或定时结束仍裁掉末尾 3 秒，保留录制前标定及融合状态快照。
- 显示归零不覆盖穿戴参考；机器人不自动启动。

## 4. 必测清单（建议 10–15 分钟）

### A. 采集与模型线程

1. 启动相机，确认彩色/深度正常、三维骨架更新。
2. 关闭三维观测，再快速开启，重复两次。应等待旧推理线程退出后恢复，
   不应出现两条推理线程并发、状态被旧线程覆盖或程序崩溃。
3. 相机保持开启，确认关闭视觉不影响 IMU 人体模型。

### B. 标定、应用与纠偏

1. 完成一次双臂一体标定，验证时长可设为 0，应用通过项。
2. 明确切到 RGB-D 融合模式，确认已通过部位继续纠偏；应用不应自动启动机器人。
3. 勾选冻结视觉，做小幅动作：补偿角保持，IMU 继续驱动；取消冻结后恢复。
4. 如平时使用视觉辅助穿戴应用/撤销，补测一次该流程。

### C. 人物恢复

1. 原标定者保持穿戴与相机位置不变，让第二人进入，发生短时遮挡后离开。
2. 有歧义时可以暂停，解除干扰且满足原跟踪条件后应能恢复原人物，不得悄悄换人。
3. 再测试“取消选择/暂停视觉”后选择原标定者并勾选确认恢复：
   不勾确认不得恢复；确认后补偿角不清零，可继续原标定纠偏。
4. 不要通过确认另一人来验证恢复，这不能保留原标定的语义。

### D. 在线换模型

1. 停止机器人与录制，保持相机采集会话不变，RTMW/YOLO26 在线切换一次。
2. 纠偏应暂停而保留补偿；旧模型观测不得继续进入反馈。
3. 等加载成功，在当前彩色框中选原标定者，勾选原标定者确认并恢复。
4. 按提示在 15 秒内斜前举/侧举，通过逐部位方向一致性检查后应恢复纠偏。
   模型间方向确实不一致的部位保持停用是预期行为，不是重构错误。

### E. 联合录制

1. 手动录制 12 秒以上后结束，再马上开启第二轮，确认按钮和状态恢复正常。
2. 预约后取消一次：应无新录制目录。
3. 定时录制一次（例如延迟 3 秒、录制 12 秒），应自动开始/结束并说明尾部 3 秒裁剪。
4. 录制时尝试换模型，应被禁止。
5. 打开其中一份记录回放，确认 IMU、RGB-D 和保存的骨架仍可读取。

### F. 相机关闭与下游回归

1. 停止相机再开启，原采集会话已变，必须提示重新标定，不能误用旧标定。
2. 正常关闭整个 GUI，无遗留采集/推理进程、卡死或异常退出。
3. 最后快速检查一次新机器人或 X1 随动、手掌和左右手指开合，确保窗口入口仍正常。
