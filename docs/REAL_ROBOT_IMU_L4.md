# 真机受限 IMU 随动：仅左肘 L4

这是独立于 X1 / CoppeliaSim 预览的实验链路。仅限已经人工验证过的
五指双臂机器人协议，不是通用机器人控制器，也未通过真机安全验收。
开发测试使用伪串口和离线数据，没有打开真实机器人串口或发送命令。

## 启动和初次验收

使用已有的人体 / RGB-D GUI，在主面板点击 **真机受限 IMU 控制…（仅左肘 L4）**。
新增依赖已在 `OptUSBProj-yolo` 安装：`ruckig==0.19.4`。
其他环境需要安装 `requirements/real-robot-demo.txt`，首次使用推荐上述环境。

1. **先不连接机器人**：分配左上臂、左前臂两个不同的在线设备，完成穿戴标定；
   或勾选手动轴映射，设置正确轴向、自然下垂归零。确认人体模型屈肘方向合理。
   只需这两个 IMU；右臂和手掌均不参与。
2. 打开窗口，查看人体屈肘角是否随伸屈变化。应为伸直约 0°、垂直约 90°。
   此时不会打开串口、发送命令。回放模式禁用入口。
3. 准备独立物理断电手段、稳定支撑和无人运动空间，关闭其他串口发送程序。
   按已有安全流程重新上电，确认真机仍为之前实测的全部角度 90°、手指控制量 0。
   **如果起始姿态不确定，不能确认，也不能开始。**
4. 选择 CP2102 对应的串口或完整 `/dev/serial/by-id/...` 路径，点击连接。
   连接本身不发送控制帧，但 USB / DTR / RTS 的电气瞬态不能由软件保证消除。
5. 点击人工确认上电姿态，勾选本次安全确认。人体左肘可采用任意舒适姿势，
   稳定保持至少 0.5 秒、波动不超过 2°，再采集人体参考。
6. 点击明确启动。**第一帧保持 L4 = 90°**。先缓慢伸肘约 3–5°，
   观察是否只有左肘运动、方向是否正确，再回到参考姿态。
   不要第一次就测试完整范围。方向不对，先暂停，修改方向并重新采集。
7. 验证暂停后，人体继续运动不应产生新指令。确认真机稳定，再重新勾选安全、
   采集参考、启动。不需要使人体与机器人姿态配准。
8. 短暂关闭选定 IMU 验证断流：应先指令侧减速，再锁定暂停；设备恢复后不会自动重启。
   检查日志和提示。结束使用时点击制动并断开，或关闭窗口；关闭过程中等待制动完成。
   **出现异常运动时使用物理断电，不要依赖窗口按钮。**

## 默认参数和映射

- 20 Hz；最大指令角速度 10°/s；最大指令角加速度 20°/s²。
- 角速度可设置上限 250°/s，角加速度可设置上限 250°/s²；仅提高可设置上限，
  启动默认仍为 10°/s、20°/s²。这些数值及新增角度范围不是已验证的真机安全范围。
- L4 指令范围固定 0–100°。界面可调频率、速度、加速度、增益及正反方向，
  活动期间冻结这些控件，修改后必须重新采集。
- 屈肘角直接来自人体模型上臂、前臂的单位骨向量：
  `θ = atan2(||u × f||, u · f)`，不运行六轴逆运动学。
- 接管采集人体参考 θ₀，并使用人工确认或正常制动后的最后指令 q₀：
  `q_target = clip(q₀ + sign × gain × (θ − θ₀), 0°, 100°)`。
- 首次 q₀ = 90°，同向模式下伸肘会降低目标、屈肘会升高目标；达到 0° 或 100° 会显示饱和。
  不会自动移动机器人来居中。正常暂停后可从最后指令相对接管。
- 始终发送协议要求的完整 54 字节帧。除了 L4 两字节及校验和，其他字节冻结：
  其余十四个角度均为 90°，十个手指控制量均为 0。

## 连续规划、故障与限制

使用本地 Ruckig 单轴、加速度受限规划，保留连续指令的 q / v / a 状态。
没有有限 jerk 上限，不应描述为 jerk 受限轨迹。每次目标变化检查轨迹的完整位置极值；
若新轨迹将越界，转为制动并暂停。目标只保留最新一帧，不积压，不密集补发追赶。
实际串口写入耗时会降低有效频率；速度 / 加速度限制针对量化前命令轨迹，
0.01° 量化后会有小台阶。它们不是实测电机速度、加速度限制。

GUI 在线程内复制人体快照，串口线程不访问 PoseEngine；两线程均检查新鲜度。
输入超过 250 ms 先减速等待；额外 250 ms 内有效新目标可平滑恢复，超窗锁定暂停。
设备/轴映射/算法/归零/穿戴参考变化、主动暂停或退出仍会锁定制动暂停，
不会自动恢复。GUI 卡顿也会由串口线程的有效期检查发现。
详见 [两级断流保护](REAL_ROBOT_SHARED_TELEOP.md#短暂断流容忍真机各-imu-模式)。
通信超时或部分写入不重试、不自动重连，起点失效；必须重新物理确认和上电。
串口使用 Linux 独占锁，但不能替代关闭其他控制程序。

**无 RXD，无法知道实际位置、跟踪滞后、碰撞、堵转或电机是否真正停止。**
正常制动后的起点仍只是最后发送指令，重新接管前应目视等待真机稳定。
外力改变姿态、机器人重启或断电后必须断开并重新确认起点。
软件暂停不是急停，也没有碰撞保护或完整双臂真机 IK 控制。
