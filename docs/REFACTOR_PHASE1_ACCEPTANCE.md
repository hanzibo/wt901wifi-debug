# 阶段 1：新机器人链路职责拆分与手动验收

阶段 0 已提交为 `deab1c2`。阶段 1 只整理 CoppeliaSim 新机器人链路，不进入融合/标定协调层的阶段 2。
数学模型、IK 权重、各组限速、手掌固定偏置、250 ms 新鲜度与 1 s 长断流判据均未更改。

## 1. 职责划分

| 模块 | 现在负责什么 |
|---|---|
| `scene_robot_gui.py` | 原窗口、配置交互、Qt 信号；SceneWorker 只调用运行服务 |
| `scene_robot_state.py` | 快照字典类型、GUI 快照采样、授权 Mailbox、新鲜度与步长规则 |
| `scene_robot_solver.py` | 人体到场景目标构造、双侧求解，返回 SolveResult |
| `scene_robot_session.py` | 单一连接、手/臂合并交换、回读检查、超时恢复与几何校验 |
| `scene_robot_runtime.py` | 循环调度、发送前授权复查、停止与清理、向界面回报 |
| `scene_robot_log.py` | JSONL 存储与相同诊断事件的 0.5 s 节流 |
| `scene_hand_profiles.py` | 手型 JSON 读写、版本/路径/角度/速度校验，不授权输出 |

原 `scene_robot_gui.py` 的 Mailbox、pose_sample、步长及诊断辅助函数仍兼容导出。
现有测试、主窗口和独立 demo 不需要同时迁移导入路径。
字典格式与现有日志事件保持兼容；没有大批修改入口或部署路径。
后台服务不导入 Qt，时钟、通信工厂、报告回调与等待函数可独立替换测试。

本阶段不是完整目录迁移。GUI 内的面板构建和配置控件先保持原样；共享数学工具暂仍沿用 X1 的模块路径。
增加了手型文件的字典形状检查：畸形 `sides` 列表返回可解释错误，不让窗口因 AttributeError 退出。

## 4. 第一轮：双臂与手腕，约 5 分钟

打开主界面的“新机器人双臂实时预览…（CoppeliaSim）”。
在连接前勾选角度/腕速/时序记录；使用原来确认过的参数。
默认仍为肩肘 120°/s、手腕 240°/s，臂段权重 0.15、分层求解、位置任务。

| 步骤 | 操作 | 通过标准 |
|---|---|---|
| 1 | 点击打开环境，确认 GPU 选项及中立场景；仿真保持停止 | 环境打开，无重复实例；画面可旋转 |
| 2 | 点击“连接 / 重新读取场景”，先不要启动跟随 | 能显示双侧回读，机器人不自行移向人体姿态 |
| 3 | 只选右臂，点击启动；慢速前举、侧举、屈肘、回中立 | 右臂连续随动，未选择的左臂保持 |
| 4 | 停止右臂，改为左臂，重复动作 | 左臂正常，右臂保持；停止后无残留追赶 |
| 5 | 停止后启用双臂，连续交替运动 30–60 秒 | 两侧均跟随，没有新增抖动或莫名停摆 |
| 6 | 启用有效手背设备的手掌朝向，保持肩肘稳定，屈腕/侧屈/旋腕 | 5/6 能跟随；分层模式下肩肘不因单纯腕目标改变而明显摆动 |
| 7 | 停止并关闭新机器人配置窗口（不关仿真），重开后把手腕速度改成 120，再连接、启动；比较后恢复 240 | 变化只影响腕部速度，肩肘行为不变 |
| 8 | 停止后分别切换向量任务、六关节联合模式，各短测再恢复默认 | 对照入口仍可运行；不要求两种算法姿态完全相同 |

固定 90° 转向沿用你之前已验证的轴与角度，不在本次重新猜轴。
改变端口/限速/记录开关时，先停止并关闭配置窗口，再重开设置、连接。
这些控件在已连接状态会禁用，单纯停止双臂不会释放它们。

## 5. 第二轮：手指独立控制，约 3 分钟

打开“左右手指姿态配置…”，加载原来的手型 JSON。

| 操作 | 通过标准 |
|---|---|
| 加载手型但不确认/不预览 | 机器人手指不自动移动，端点仍需明确确认 |
| 分别确认张开、闭合，预览左手再右手 | 只动对应侧手指；停止时保持末次姿态 |
| 打开原左右手 IMU 夹爪配置，采集或使用本轮有效手势参考，启用新机器人输出 | 离散张开/闭合正确映射到各侧手型 |
| 双手同时开合，再叠加双臂随动 | 两侧不串手；不影响肩肘/腕部配置 |
| 停止双臂但继续手势 | 双臂停止，手指通道仍独立工作 |
| 点击“停止左右手指输出”并继续动作 | 手指保持，不因旧请求再次移动 |
| 关闭手型窗口再重开 | 手指输出停用，不自行恢复；已有未编辑端点可以保留确认 |
| 关闭新机器人窗口再重开 | 没有后台旧输出；重新连接后需再次确认手型并启用输出 |

未准备四台手势设备时先测单侧，未测另一侧请明确记录，不把单侧通过当作双侧通过。
保存手型时另存到临时文件；不要覆盖你已有的 `hand_poses.json`，本轮保留了其未提交修改。

## 6. 第三轮：失流、重连与日志

仅在仿真中进行：关闭一台当前所选的臂部 IMU 超过 1 秒。
应看到具体设备的新鲜度提示，机器人保持当前角度，最终停止本轮。
设备恢复后不应自动重新授权启动；按原流程处理设备/参考，再明确启动。
短于 1 秒的自然断流若出现，应等待新数据并按原速恢复，不补发积压姿态。
不建议用人工快速开关机来“精确制造”短断流，它可能改变积分参考，不能等价比较。

先停止双臂和手指，再正常关闭 CoppeliaSim，确认窗口显示通信失败/停止。
重新打开环境、重新连接；不能自己开始运动。明确启用后应能再次跟随。
若有保存/退出确认弹窗，按正常流程处理，不必故意制造阻塞弹窗。

本轮日志位于：

```text
/home/hzb/Work/WT901/OptUSBProj-ubuntu/recordings/coppeliasim/
  时间戳.jsonl
  时间戳.ingress.jsonl
```

检查窗口显示的日志路径。关闭新机器人窗口后再反馈，便于读取完整文件。
日志应仍有 config、角度回读、timing、wrist_diagnostics、手指 hands 事件及停止/超时原因。
记录关闭/重连时会产生新会话文件，反馈时请提供对应各轮路径。
