# 真机五指：双 IMU 离散开合（实验）

入口：人体 GUI → 真机受限 IMU 控制 → 左臂或双臂仿真同源 IK → **五指端点 / Checkpoint / 输出许可**。

## 数据与权限边界

- 每侧手背 IMU 与指段 IMU 的相对转动，经过开手/闭合参考、平滑、双阈值和持续确认，得到一个二元状态。每手两台不同设备，双手四台角色不得重复；手背可复用该侧手掌朝向输入。复用主窗口姿态，不重复积分、不另占 UDP 1399。
- 每手五个协议通道，各自设置张开量、闭合量、最小/最大量、速度及加速度；五指共用该手的二元状态，不能测量各指姿态。界面暂称“协议指1–5”，须小幅逐个确认真实指序及方向。
- **0–4095 是协议数量，不是角度，不是已验证机械限位。** 默认端点 0/200、区间 0–200、速度 200 量/s、加速度 400 量/s²只是初始试验参数，不是硬件安全认证。
- 默认十指许可全部关闭。只有健康的同源跟随阶段才能逐手明确授权；首帧保持最后写出量，后续使用限速/限加速度轨迹。发送频率共用真机面板设置。
- 真机手势有独立的平滑和双阈值状态，默认离轴残差超过 20°时无效。每手可单独勾选“真机：允许离轴残差超过 20°仍应用开合”，此时仍使用独立真机平滑及双阈值判定，不要求同时开启仿真“残差仅提示”。放宽可能增加误判，不是对输入准确性的认证。
- 真机残差开关默认关闭，不写入手型 Checkpoint。切换会停用该手、清除旧判定并重新累计阈值确认时间；输入恢复后仍须明确启用和二次确认。开关不绕过断流、新鲜度、参考/设备变更、采样中或非有限值检查。
- 双臂与手指只有一个串口发送线程，合并成同一个 54 字节帧；不创建第二串口连接。不得同时运行手动串口或电位器 demo。

## 操作顺序

1. 机器人安全重新上电；按原流程连接、确认上电构型，启动左臂或双臂同源跟随。暂不启用手指。
2. 打开五指配置中的“双 IMU 开手 / 闭合参考与阈值配置”。选择设备，先采开手参考、再采舒适闭合参考，观察状态切换是否稳定。无需勾选 RViz/CoppeliaSim 输出。
3. 回到五指配置。首次只许可一侧一个协议指；使用已确认的小范围端点，确认空间、指序和独立断电手段后点击“明确启用”，再接受二次确认。并非一勾选就发送。
4. 做开/合变化，检查真机与显示指令。停用该手并等待指令侧减速结束，才可修改其配置。逐指完成后再尝试单手五指、最后双手。
5. 可保存、加载独立手型 Checkpoint。加载后许可全部清除，手势需重新判定，不自动运动。

五指窗口在尚未授权时也实时显示手势开/合、有效性、离轴残差、数据年龄和残差策略。“暂不可启用”会列出缺少的条件，例如串口未连接、安全许可未确认、尚未进入同源跟随、没有勾选手指或手势数据无效。手臂刚接管到位但仍在等待确认时，不能启用手指；先完成原有开始同源跟随步骤。

## 暂停、断流与回位

手势无效或最后有效同期数据超过 250 ms，先减速等待；自最后有效数据起超过 500 ms仍未恢复，则锁存停用该手。仅在短暂窗口内、参考未变且新鲜有效数据恢复时可继续。硬超时、参考/算法/设备变化及手动停用后，均须明确重新启用，不自动恢复。

单手输入问题可以只停该手，健康的手臂继续；全局暂停、结束姿态触发、关闭/断开或顺序回位会停用全部手指，等待指令侧减速后才结束发送。轨迹异常、部分串口写入等仍遵守原有失败断连规则。

**臂顺序回位保持末次手指量，不自动把手指归零。** 臂回位完成后，若手指非零，可点击“手指平滑回零（臂回位后，二次确认）”：

1. 人工确认双臂实际已稳定、手中没有物体、张开路径安全。
2. 程序从末次成功写出的指令量开始，按本次会话中各指最后授权的速度/加速度平滑回到协议 0。首帧保持起点，双臂和头腰固定在 90°；未动过的零值手指不改变。
3. 指令侧回零完成后，人工确认真实手指也稳定到位，再点击“确认真机实际已回上电姿态”。之后重新确认安全、锁定目标并明确启动；不会自动随动。

手指回零是明确授权的自主任务，不依赖 IMU。全局暂停、断开/关闭和界面心跳超时仍会让它减速停止；中断后不自动继续，也不能冒充完成。回零期间请使用真机主窗口的暂停/断开控制，不要把双 IMU 窗口的仿真输出停止按钮当成真机停止。

仅允许本次连接、同源会话内曾明确授权的手指回零，且其最后授权区间必须包含 0；不因回零扩大软件范围或新增右手许可。若范围不含 0、许可记录丢失、连接异常或起点不可信，仍拒绝回零/确认，须物理检查并安全重新上电。非零手指始终不能被“确认”按钮直接忽略。

以上减速、停留和回位均基于已发送指令，不是实测到位或物理急停。没有接触力、夹持力或碰撞反馈；手势停止也不能替代独立断电措施。不要夹持物体或让身体进入机器人运动范围。

## Checkpoint 与记录

手型预设独立保存在 `OptUSBProj-ubuntu/config/real_robot_hand_checkpoints/`，版本 1 JSON；不与臂参数或仿真十五关节端点混用。保存左右手的端点、区间、速度和加速度，**不保存输出许可、串口、参考或运行状态**。全文件验证通过后才覆盖界面，运行/减速期间禁止加载。

原有 `recordings/real_robot_imu/<会话>/control.jsonl` 新增 `hand_observation`、`hand_enabled`、`hand_stop`、`finger_return_requested`；`write` 中增加各手状态、指令量、目标、速度和加速度，手指回零任务另有 `finger_return` 状态。它们是上位机数据，不是真机位置反馈。

镜像使用成功写出的完整帧，同步显示手指名义构型。每协议指按历史比例近似映射到仿真三个指关节（4095 对应历史各指最大弯曲角）；**没有逐指硬件标定，不能把仿真手型当作真实手指角度**。镜像仍要求已核对几何、停止的原场景；不要同时启动独立仿真手指输出，以免争写场景。

## 手工验收清单

- 未连接/未跟随/未许可时，打开窗口、加载预设和变换手势均不驱动手指。
- 单指小幅测试开合方向；其余九指和头腰保持，臂继续跟随。每个协议指分别验证，逐步确认可用端点。
- 手指运动中点击该手停用：减速保持；再做开合不自动恢复，另侧及双臂不受影响。
- 全局暂停或结束姿态：臂、手指共同停止；臂回位不意外改变手指量。随后明确执行手指平滑回零，双臂/头腰应保持不动；完成后才可人工确认全机上电态。回零中暂停应减速保持，不自动继续。
- 正常运行中停发某侧指段 IMU：短暂断流容忍、超过 500 ms锁存该手停用；恢复设备后不会自行启动。不要通过拔机器人控制 USB 来测试 IMU 丢包。
- 保存不同手型再加载，参数完整还原、许可清空；仿真预设不会误载为真机预设。
- 使用同一组双 IMU 观测对比严格/放宽模式：超过 20°时严格模式拒绝；放宽模式可重新判定及明确启用。运动中切换会停用该手，绝不自动重启；超过 500 ms断流仍锁存停止。
- 双手独立开合、镜像显示及日志最后一起验证。若真机有抽动、堵转或越界趋势，立即使用独立断电手段，不继续扩大范围。
