# X1 实验性自碰撞检测与拦截

本功能仅用于 RViz 运动学预览，不向实体机器人下发命令，不是安全认证方案。

## 操作

1. 更新代码后，关闭旧 ROS 接收进程再重新启动 GUI。关闭 X1 弹窗本身不会结束模型进程。
2. 首次验收使用全新、零角状态的 RViz 模型；不要同时运行关节滑杆或其他 `/joint_states` 发布器。
3. 在“X1 双臂实时 RViz 预览”中，勾选“启用自碰撞检测与拦截（实验）”，再启动 ROS 接收及随动。复选框默认关闭。
4. 等待保护状态从“初始化”变为“正常”。需要切换保护时先停止双臂随动，并停用手机／双 IMU 夹爪输入，等待约半秒再切换。
5. 靠近碰撞边界时可能显示“截短”或“已拦截”，候选目标可能达不到。检查失败、超时或工作进程异常时，不放行未经检查的新角度。

显示包含状态、原因、最近采样距离、相关连杆及检查耗时。最近采样距离不是整条运动路径的精确最小距离。接收 ACK 只证明收包，不能代表角度已通过检查或已发布。

## 发布链与两个环境

GUI 求解候选双臂角度；ROS 桥合并双臂、头部及夹爪状态后，将完整关节配置交给独立工作进程。通过检查后，桥才更新已接受状态；否则保持上一已验证状态。保护开启时，下一帧 IK 的关节连续性参考来自已接受状态，而非被拦截的候选解。

- `x1_ros2_py`：ROS 接收、唯一 JointState 发布器、标准库异步门控。
- `OptUSBProj-yolo`：`python-fcl`、`trimesh`、NumPy、SciPy；加载几何及执行检查。
- 通过私有子进程管道通信，不新增网络碰撞服务。GUI 启动桥时传入工作进程解释器；手动启动可使用 `--collision-python /home/hzb/miniconda3/envs/OptUSBProj-yolo/bin/python`。
- `--collision-start-enabled` 可使新桥从启动时就开启拦截；初始化未通过前不发布未经验证的初始状态。

## 几何及运动路径

从完整 URDF 读取固定／旋转关节、origin、axis、collision origin、mesh scale 与 STL。当前模型含 23 个 link、22 个碰撞形状、16 个运动关节；双臂、夹爪、头部及固定附件都参与完整 FK。

一般 STL 使用包围它的凸包作保守检测几何。躯干 `base_link_0` 和肩部 `L2/R52` 改为复合凸包：先按 CAD 连通零件拆分，再进行 6 层空间切分，每个片段建立凸包。跨切面的三角形进行裁剪而不是丢弃；新切面添加保守凸封盖，防止继续切分时漏掉实体内部区域；孤立三角形和退化平面片段保留为微厚包络。几何加载后在工作进程内复用，首次初始化约需数秒。

完整凸包用于快速粗筛，近距离／相交时再用 FCL 原生 AABB 树查询复合凸体间距。粗筛也包含微厚片段，避免包络和路径位移界不一致。复合凸包仍会填满局部凹陷，不是精确三角网格接触结果，也不是经过认证的实体模型；原 STL 含不封闭组件，对这些组件的实体解释仍依赖 CAD 模型假设。

固定连接组成刚体组。组内以及代码明确列出的相邻关节装配组不做互检，其余当前共 200 对。这是实验性装配接触假设，不是证明相邻零件在任何角度都不会碰撞；也没有以“中立位已碰撞”为理由自动生成白名单。

一般安全间隙为 2 mm。躯干与 L2／R52 两对仍检查；旧的整体凸包在零角下间隙仅约 0.28／0.33 mm，复合凸包约为 1.22 mm，本轮保留这两对原有的 0.1 mm 特殊阈值，没有通过全局降低门限解决误拦截。此阈值只用于预览 CAD 容差，不能解释为真实机器人的安全间隙。

检查覆盖从上一接受配置到候选配置的关节线性插值路径，而非只检测终点。每次在区间中点计算距离，并用关节运动引起的保守距离变化上界验证整个区间；无法证明安全的区间继续细分。达到预算／细分深度后仍无法验证，按不通过处理。

单次验证预算 25 ms；整次请求最多约 90 ms。若完整步不通过，依次尝试原步的 1/2、1/4、1/8、1/16，每个前缀都必须独立验证整段安全才能发布。未找到安全小步就保持原位。这不是绕障路径规划；可能卡在边界，需改变人体目标姿态。

末级运动关节的位移界使用碰撞几何到关节轴的最大垂直距离，代替较松的平移长度之和；该半径在自身旋转下不变，只用于后续关节全为固定连接的情况。其他关节仍使用原有保守上界。不以离散采样替代整段路径认证。

预算在 FCL 查询之间和复合查询回调中检查，无法强制中断一次原生查询；桥还检查响应超时，超时结果不接受。异步机制避免在 ROS 主线程执行几何计算，但不保证每个候选帧都在 30 Hz 下放行。

诊断区分 `collision`（检测包络相交）、`clearance`（间距低于余量）、`timeout`（预算耗尽，未确认）、`unverified`（路径无法认证）和 `invalid`（配置无效）。全部拒绝未经验证的新角度。FCL 返回的负距离仅表示相交，界面不再把它显示成负一米的“穿透深度”。缩步结果同时保留原目标的检查原因。

## 范围与局限

- 仅检查机器人自碰撞，不包含桌面、人体或外部障碍物，也不含动力学、制动距离、力控或真实执行器误差。
- 新桥按零角建立初始账本，不读取 RViz 上一个进程残留的姿态；跨桥重启时必须使用零角模型。路径保证只针对当前桥已知状态，不能覆盖其他发布器偷偷修改的姿态。
- 一旦在关闭保护时进入碰撞构型，再开启会拒绝初始构型，不能自动生成脱困运动。停止输入并重新建立零角预览后再验收。
- OFF 模式保留原预览链，不能解读为安全模式；实验开关不是实体机器人的急停开关。
- URDF 限位、几何版本及接触排除规则改变都需要重新验收。
