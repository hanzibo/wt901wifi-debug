# 左臂仿真同源接管（实验，无位置反馈）

主窗口的真机受限 IMU 控制窗口新增第三种模式：
**左臂仿真同源 IK（上电姿态平滑接管）**。
原单肘模式和六轴相对接管模式仍然保留。

左臂 / 双臂同源模式支持[参数 Checkpoint 管理](REAL_ROBOT_CHECKPOINTS.md)：
停止信号开关、持续时间（默认 7 秒，可调 0.1–120 秒）与每侧回位顺序、速度、加速度、
步间停留也可保存。下文 7 秒验收示例以默认值为例；运行时以界面选定时间为准。
保存关节上下界、速度 / 加速度以及所选停止姿态的参考角 / 容差；加载不启动运动，须重新确认安全。

## 制动临界点的数值处理

当目标在浮点舍入精度内等于 `q + v·|v|/(2·a_max)` 时，使用解析等减速轨迹，
避免加速度约束 Ruckig 在此退化边界报 Step 1 错误。这不是忽略规划失败或跳到目标；
仍按发送周期连续采样，保留速度、加速度、完整轨迹极值和逐帧范围检查。
此分支仅适用于当前未设置有限 jerk、终点速度和加速度为零的规划模式。
日志 `planning_methods`（单肘为 `planning_method`）标明 `analytic_stop` 或 `ruckig`。
一般目标和其他规划错误仍按原规则处理，超时或显式停止仍锁存，不自动恢复。

## 同源的含义

`SharedArmIK` 直接调用现有 `SceneSolver`，不是重写一套 IK。
使用 STL 自然下垂参考、肘腕位置、统一长度比例、臂段朝向软约束 0.15，
以及分层求解（1–4 臂段、5–6 手腕）。手掌目标默认开启；固定转向可独立关闭。
转向支持局部 X/Y/Z 和 −180° 至 +180°，无已有配置时默认 Z +90°、不启用。
需三个不同的在线左侧 IMU。
如果仿真配置窗口已打开，创建真机窗口时复制其左手转向的启用状态、轴和角度。
之后可点击“复制仿真窗口左手转向配置”重新同步；不会在运行中自动覆盖配置。
更改转向配置会使已锁定目标失效，须重新锁定；控制期间配置不可编辑。
勾选转向且开启手掌朝向任务后才会施加补偿。

场景角到协议角为 `90 + sign * degrees(q)`。双臂原始代码支持默认 +1 映射；
第三种模式仅开放左臂；第四种双臂模式可逐轴开放两臂。头腰维持 90°，手指维持 0。
不要将场景角再套用原 DH→场景转换。

求解范围使用真机窗口的用户配置。IK 种子从下垂中立位开始，
但真实发送轨迹从人工确认的全部 90° 上电姿态开始。
这些是两个独立参考，不能把 IK 的参考姿态改成串口起点。
IK 不额外套仿真单步限速，指令轨迹器独立约束每轴速度和加速度。

| 轴 | 最小 ° | 最大 ° | 速度 °/s | 加速度 °/s² | 方向 |
|---|---:|---:|---:|---:|---:|
| L1 | 0 | 226 | 100 | 150 | +1 |
| L2 | 90 | 233 | 100 | 150 | +1 |
| L3 | 0 | 180 | 100 | 150 | +1 |
| L4 | 0 | 119 | 100 | 150 | +1 |
| L5 | 0 | 180 | 100 | 150 | +1 |
| L6 | 51 | 122 | 100 | 150 | +1 |

发送默认 20 Hz；六轴默认勾选，但不自动连接、不自动发送。
软件范围不是机械限位认证，也不是碰撞保护。

## 接管步骤

1. 真机重新上电，确保实际仍处于全部 90° / 手指 0 的已知姿态。
   在场看护并准备独立物理断电。关闭手动串口 demo。
2. 启用并分配左上臂、左前臂、左手背 IMU。自然下垂归零。
   使用穿戴标定或窗口的手动轴映射。
3. 选择第三种模式。首次验证取消其他五轴，只勾选 L4。
   先调低速度、加速度，并选择确认安全的姿态和范围。
4. 连接串口（不发送），确认上电姿态，勾选安全许可。
5. 保持人体稳定至少 0.5 秒，点击“锁定当前同源目标”。
6. 点击明确启动，检查弹窗内的勾选轴目标，再确认过渡路径安全。
   首帧为确认的上电帧；随后连续平滑过渡到固定目标。
7. 过渡期间保持人体不动。超过 2° 朝向变化或设备/标定变化会触发
   指令侧制动，不自动恢复。短暂输入断流适用下述两级保护。
8. 显示“过渡指令已完成”后，观察真机是否已稳定。
   点击“确认真机已稳定到位，开始同源跟随”，再次人工确认。
   跟随复用同一轨迹器，不在切换处跳角。
9. 先慢速屈肘验证。再逐轴验证方向，最后组合轴。
   同源模式暂停后不从未知姿态重新接管；须重新上电并重新连接确认。

没有 RXD/实际角回传，程序不能判断真机是否真正到位。
串口写入成功、轨迹终点、仿真镜像均不能替代实际角度测量。
限速不保证路径无碰撞；此版本未恢复防碰撞功能。

## 可选 CoppeliaSim 镜像

手动打开 `robot-urdf-model-new/NowRobotWithHand1.ttt`，保持仿真停止。
断开原“新机器人双臂实时预览”窗口的连接。
勾选真机窗口的镜像复选框，连接本机 23000 端口。
连接时校验左臂几何；第四种模式同时校验右臂及两侧手掌几何，**不设置关节角**。不自动保存或启动仿真。

串口完成整帧写入后，镜像线程接收这份最终量化帧。
按协议反算左右臂场景角，仅最新帧覆盖，不排队回放。
未勾选轴在仿真中也保持上电值；第三种模式右臂镜像为零场景角。
第四种模式按左右两套方向符号分别反算，镜像最终发送的双臂指令。
头腰/手指不由镜像控制，请保留原场景的上电状态。
镜像是指令预览，不是真机反馈；真机固件延迟仍可能造成视觉差异。
原独立预览与同源镜像互斥，避免两个写入者。
镜像失败会请求真机指令侧制动，不自动重连或继续发送旧角。

## 日志与离线测试

排查短时断流时，保留整个 `recordings/real_robot_imu/<本次>/` 目录：

- `arm_input_timing`：GUI 轮询间隔，以及每台设备 ID、接收时刻、当前年龄、是否更新；
  即使姿态检查失败也记录实时观察，不再仅依赖最后一个有效快照的年龄。
- `arm_ik_submit`：序号、输入有效期、输入时间线、是否覆盖待处理目标。
- `arm_ik_discard`：在求解前或求解后过期、排队耗时及求解耗时；不会延长原始有效期。
- `arm_ik.timing`：提交时刻、队列耗时、求解结束时刻、GUI 接收时刻和信号送达延迟。
- `arm_ik_gui_discard`：已经求完但送达 GUI 时过期的结果。
- `arm_target_received`：串口线程接收最新目标的间隔、获取锁的等待时间和来源时间线。
- `input_timeout`：首次触发的有效期、超期毫秒数、距最后目标更新的时间和最后来源时间线。

以上是软件观测，不等同于无线原始包抓取，也不是机器人位置反馈。
连接真机控制窗口后，若当前数据源支持，将自动向同一 `control.jsonl` 写入
`acquisition` 事件；`source_event` 区分以下阶段：

- `udp_datagram`：应用读取数据的单调/墙上时钟、发送端、字节数；Linux 支持时同时
  记录 `kernel_received_wall_ns` 和 `socket_queue_ms`，即内核收到包到应用读取的等待。
- `udp_parse` / `imu_parsed`：解码包数量、丢弃字节、设备 ID、设备时间、RSSI 和解码时刻。
- `main_gui_poll_begin` / `main_gui_batch`：主窗口取包间隔、耗时和批次大小。
- `pose_engine_feed`：从应用读包到姿态模型处理的延迟、处理耗时及模型采用的时间戳。

不另开 UDP 监听，不发送设备配置指令；断开后解除本次观察，不影响其他诊断消费者。
内核时间为实时时钟，其他阶段用单调时钟；系统校时可能影响 `socket_queue_ms`，
不把两种绝对时间直接相减。字段为空表示内核时间戳不可用，不表示延迟为零。
内核收到包仍不等同于传感器发包时刻，无法仅靠这些日志区分无线丢包和设备停发。
上述字段仅用于观察；短暂断流处理见下一节。

### 短暂断流容忍（真机各 IMU 模式）

- 保留 250 ms 的输入新鲜度要求；过期姿态不进入 IK，过期 IK 结果不发布。
- 最后有效目标过期后进入 `gap`：立即改为原限加速度下的减速目标，不继续追赶
  旧目标、不外推人体动作。减速到零后仍等待；界面明确显示断流等待。
- 从原目标有效期末尾起额外容忍 250 ms（共约 500 ms 源数据年龄预算，包含
  GUI / IK 延迟）。只有在此窗口内到达串口线程的有效新目标能恢复；沿用当前
  指令角、速度和加速度规划，不跳角、不回放历史队列。双臂统一减速/恢复。
- 超窗则锁定制动暂停，即使随后数据恢复也不自动继续。用户暂停、配置/签名变化、
  IK/镜像异常、通信错误仍沿用不可自动恢复的保护。回位任务不受此机制影响。
- 接管启动时输入仍须新鲜；上电过渡恢复仍使用原先锁定的固定目标；断流期间
  不接受“开始跟随”确认，恢复后再人工确认。
- 日志新增 `input_gap_started`（原有效期及固定硬截止）和 `input_gap_recovered`；
  超窗记录 `input_timeout`，其中 `grace_ms=250`。有效期不会因持续过期更新而后移。

这只是指令侧保护，不是实体制动、通信确认或碰撞保护。单向 UART 无法撤销
厂商固件可能已缓存的指令；自动恢复仍可能在人体姿态已变化时产生运动。
先用小范围、低速、单轴验证，准备独立断电手段。

仍记录在 `recordings/real_robot_imu/<本次>/control.jsonl`。
新增 `shared_transition`、`shared_follow_confirmed`，以及 write 行中的
`phase`：transition / await_confirmation / following。
`arm_model.task_mode` 区分 simulation_shared 与 relative。
`arm_model.palm_offset` 记录 enabled、axis、degrees，不再假定偏置仅为 X 轴。

测试覆盖纯轨迹、同源目标、量化帧镜像、假仿真生命周期，以及
`/dev/pts` 虚拟串口下的完整 GUI 过渡→确认→跟随→暂停。
这些自动化测试不会连接真实串口或启动 CoppeliaSim。

## 双臂模式与现场验收（第四种模式）

新增“**双臂仿真同源 IK（可逐轴启用左 / 右臂）**”。两侧使用独立导出的场景几何，
复用同一 SceneSolver 目标函数：肘腕位置、臂段朝向软约束、可选手掌朝向，
分层求解 1–4 与 5–6。只有勾选轴才可发送；右臂默认全关闭，左臂保留原配置。
两臂共用一帧 54-byte 指令、发送频率、过渡/确认状态机和减速暂停决策，
不是两个独立串口写入者。日志目标、command、velocity、acceleration、enabled
均按 **R1..R6，L1..L6** 排列，names 字段标识名称。
右侧掌向和固定转向单独配置，可复制原仿真窗口右手设置。

右臂默认包络（°）：R1 0–235、R2 90–240、R3 0–180、R4 0–118、
R5 0–180、R6 50–121；来自师兄原 PC 软件，**尚非现场验证限位**。
默认速度 100°/s、加速度 150°/s²，发送频率 20 Hz。
左右方向各自可调；不会根据 L6 的实测方向推断 R6。切换模式不重置左臂方向设置。
仅右侧有许可时仅要求右上臂/前臂/手背三台设备；仅左侧同理；两侧有许可需六台不同设备。
任一参与侧输入超过上述容忍窗口、签名变化、IK/镜像错误会暂停所有参与轴，不自动恢复。

现场测试顺序：

1. 关闭旧真机窗口并重开更新后的程序，关闭手动串口 demo。准备独立断电、清空周围空间。
2. 重新上电，确认全 90° / 手指 0。选择第四种模式；暂时取消全部左臂输出，仅勾选 **R4**。
   将 R4 范围缩到确认安全的小区间，例如围绕上电 90°，并降低速度/加速度。
   这些值由现场确认，不将完整默认包络当成已验证机械限位。
3. 分配右侧三台不同 IMU，自然下垂归零；必要时启用手动映射。
   连接串口不发送→确认上电姿态→安全许可→锁定稳定目标→明确启动。
   检查弹窗目标，过渡后人工确认真机到位，再慢速屈肘。
4. 分别验证 R1、R2、R3、R5、R6 的方向和小区间响应。尤其 R6 不预设与 L6 同向。
   修改许可/范围/方向前暂停；每次重新接管均重新上电和确认。
5. 保留已验证的左侧参数，先同时勾选 **L4 + R4**，六台设备在线，慢速双肘测试。
   确认未勾选肩/腕、头腰和手指没有运动。
6. 再逐渐开放已验证轴；可勾选 CoppeliaSim 镜像，用原 NowRobotWithHand1.ttt 停止场景对照。
   单臂动作、交替双臂、同时双臂均测试；勿交叉挤压身体/两臂，当前无防碰撞保护。
7. 安全静止时断开一个参与 IMU，确认界面指出部位且两侧都暂停、恢复设备后不自动继续。
   测试暂停/断开按钮，并提供本次 control.jsonl 供检查。

自动化覆盖右侧真实导出几何、同源目标、双臂权限和协议顺序、方向反算、
右侧几何不匹配拒绝镜像、单侧传感器选择，以及虚拟串口双肘完整流程/右侧断流。
这些证据是软件链路验证，不能证明实体角度准确、机械限位或防碰撞安全。

## 侧举 / 前举结束信号与手动顺序回位

“停止姿态（二选一）”可选侧举（原 T 型）或前举；只显示并检测当前所选姿态的轴：

| 控制模式 | 侧举 | 前举 |
| --- | --- | --- |
| 左臂同源 IK | L2 / L4 | L1 / L2 / L4 |
| 双臂同源 IK | R2 / R4 / L2 / L4 | R1 / R2 / R4 / L1 / L2 / L4 |

每轴独立设置参考协议角和容差，所有检测轴须同时获得输出许可。
连续满足自定义保持时间才减速暂停；任一检测轴离开容差、输入过期或发送间隔过长均重新计时。
非检测轴的转动不参与判断；仅左臂模式不要求右侧满足姿态或获得输出许可。
只在 following 阶段计时，接管过渡、等待、回位阶段均不触发结束检测。

默认仍选择侧举且检测关闭，90°仅是待核对占位值。前举角度同样须实测填写，
或在实体确实处于选定姿态时采集最后成功发送的指令作参考，不能从名称推定角度。
切换类型清除参考确认与接管参考，运行和倒计时中不可切换。
Checkpoint 可保存类型及其对应参数；旧预设按侧举加载，加载不恢复安全或姿态参考确认。

首次前举验收：先用左臂低速验证L1/L2/L4均在范围内时才计时，任一轴离开范围计时清零；
保持不足设定时长不触发，满时长后暂停且不自动恢复 / 回位；再验证双臂六轴。
准备独立断电手段，核对所有运动路径，勿用结束姿态检测代替硬件急停。
日志 `end_gesture_status` 的 config 和 `end_gesture_triggered` 包含 kind 与检测 indices（从0开始）。

以下旧 T 型验收步骤仅适用于选择“侧举停止”，前举请按上表配置检测轴。

### 先用左臂验证

选择“左臂仿真同源 IK”，结束配置只显示 **L2 / L4**，不要求右侧 IMU 或右轴许可。
按实际验证的特定姿态填写两轴协议参考角与容差，点击确认参考后勾选检测；
L2、L4 必须同时获得输出许可。过渡阶段不计时，仅正式随动阶段连续满足 7 秒触发暂停。
默认参考 90° 不是推荐的结束姿态，必须自行确认，不要直接照用。

暂停稳定后手动启动回位，左臂按 **1→3→5→6→4→2** 返回 90°；
右臂、头腰保持 90°，手指保持 0。没有获准输出且已处于 90° 的轴跳过，
没有许可但不在 90° 的轴会拒绝回位。默认低速、逐步确认；最后人工确认实体回位，
然后重新采集目标与明确启动。回位不自动触发，不会因移动人体自动恢复。

“一键连续顺序回位”按钮可直接启动连续执行，无需取消逐步确认复选框。
一次弹窗确认后，沿用当前先后顺序、速度、加速度和步间停留，依次执行所有获准轴；
执行期间不能重复启动，仍可使用减速暂停。完成后仍须人工确认实体已实际回位。
取消弹窗不发送指令；按钮不会改变逐步确认复选框，原逐步操作保留。

请先在可控空间低速验证：不足 7 秒不触发；离开容差后重新计时；触发后暂停；
回位过程中人体运动不改变目标；回位后未人工确认时不可重新接管。

### 双臂及通用边界

第三种左臂同源与第四种双臂同源模式均提供这组操作。默认关闭 T 型检测；界面的 90°
是待配置占位值，不是已标定的 T 型角度。先在安全的小范围单轴测试中确认
左右第 2、4 关节的 T 型协议角，然后暂停，手动填写并确认四个参考值；
也可在已暂停、实体确实处于 T 型时，从最后成功发送的指令帧采集参考。
设置每轴容差后确认，再开启检测。修改参考/容差后须重新确认。

检测只在 following 阶段计时，依据成功写出的 R2/R4/L2/L4 指令，
这四轴必须都有输出许可。四轴连续在容差内 7 秒才触发统一减速暂停；
超范围、输入不新鲜或发送间隔过长会清零计时。倒计时期间仍随动，
触发后不自动恢复，也不自动回位。它不是急停或实体姿态检测。

暂停后观察实体已稳定，回到电脑前单独操作“顺序回位”。默认左臂→右臂，
每臂 **1→3→5→6→4→2**；仅处理本次获得许可的非 90° 轴。
无许可且非 90° 的轴会拒绝完整回位，任何回位轴范围必须包含 90°。
回位使用最后成功发送的帧作为起点，不读取人体目标；仍由原串口线程发送，
镜像仍使用最终指令帧。默认回位速度 10°/s、加速度 20°/s²、每步停留 0.5 秒，
并逐步人工确认；可自行调整顺序、先回哪侧和是否逐步确认。

建议现场验收：

1. 先用小范围双肘许可测试结束检测；配置真实参考，分别验证不足 7 秒、
   中途离开容差、重新计时与触发后不自动恢复。
2. 准备独立断电手段，检查全路径空间。低速逐步回位，每一步观察实体是否
   稳定及下一轴是否会碰撞，再点击下一步；不要仅依据仿真或指令完成提示。
3. 验证回位时移动人体不会改写目标；测试减速暂停，并确认暂停后不自动继续。
4. 所有回位指令完成后，人工核对实体全 90° 上电姿态，点击“确认实际回位”。
   之后才允许重新采集目标、重新授予安全许可并接管；不会自动开始随动。
5. 检查日志 end_gesture_status、end_gesture_triggered、return_step、
   return_commands_complete、home_manually_confirmed，并保留记录供复核。

**此顺序只是用户指定的候选路径，不保证消除碰撞。** 没有位置反馈，
停留时间也不证明电机到位；单向 UART 不能撤销固件中可能已缓存的指令。
若卡顿、异响或路径异常，应使用独立断电手段，不依赖姿态检测。

## 可调过渡容差与可选倒计时接管

左臂 / 双臂同源 IK 均有“同源接管设置 / 倒计时自动启动”。原来的采集、明确启动、
人工确认真机到位流程仍保留，过渡检查改用此处的容差（默认 2°，范围 0.1–30°）。
超差提示包含具体侧别、上臂 / 前臂 / 手掌、实测人体朝向变化和阈值；暂停原因也显示在
启动诊断中，暂停后到位确认按钮禁用，不会自动恢复。此容差不改变 IK 或机器人机械范围。

自动流程每次均需单独二次确认：

1. 确认上电起点、逐轴许可、范围 / 速度 / 加速度、安全空间及独立断电手段。
2. 点击“倒计时锁定目标 → 平滑接管 → 自动跟随…”，在弹窗核对后明确同意。
3. 倒计时默认 10 秒，此时不锁定握鼠标的姿态，也不发送运动指令。
   离开鼠标摆好人体姿态，至少稳定 0.5 秒（连续采样且朝向波动不超过 2°）。
4. 到时锁定当时的目标，用现有 IK / 限速 / 限加速度平滑接管。过渡及等待期间保持人体不动。
5. 指令轨迹完成后，默认再等 2 秒，自动开始跟随，不再要求用鼠标确认到位。

**这一步是用户预先授权的开环流程，不是实际到位检测。** 厂商执行延迟仍可能存在，
必须先用已验证的小范围单轴测试并观察真机；不能仅凭软件等待来推定已稳定。
若仍需人工确认到位，继续使用原逐步流程。

倒计时可设 1–120 秒；完成后等待可设 0–30 秒。三项均可存入模式独立的 Checkpoint，
但授权和运动状态不会保存。自动流程中不能加载预设或修改配置；“取消自动流程”始终可用。
倒计时末输入不连续 / 不稳定则立即取消，不无限等待；输入无效、设备签名 / 配置 / 安全许可
变化、控制进入断流 / 减速 / 暂停、界面调度停顿超过 0.5 秒都会取消本次自动流程，运动中请求
指令侧减速，不自动重试。正常跟随开始后沿用已有短暂断流容忍机制。

### 本次手动验收

1. 先不连接真机，保存 / 另存 / 加载含三项新参数的 Checkpoint，核对两模式独立、加载不授权。
2. 在可控空间仅许可一个已验证轴、小范围低速：取消二次弹窗应无动作；授权后取消倒计时也应无动作。
3. 正常倒计时，离开鼠标摆好姿态，确认到期才锁定并平滑接管、指令完成及等待后自动跟随。
4. 倒计时末仍在移动应取消；低速过渡中超出设定容差应暂停，诊断应指出具体侧别 / 部位和变化角。
   重新接管须先按原流程恢复并确认上电起点，不从异常暂停位置擅自重启。
5. 验证原逐步启动仍可用；单臂通过后再低速验证双臂。保留 control.jsonl 供复核，
   日志包含 auto_start_authorized / auto_start_settling / auto_start_completed 或 auto_start_cancelled。
