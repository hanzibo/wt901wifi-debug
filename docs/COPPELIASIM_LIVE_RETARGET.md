# 新机器人 CoppeliaSim 双臂实时预览

## 使用步骤

1. 打开已确认中立构型的 `robot-urdf-model-new/NowRobotWithHand1_teleop_neutral.ttt`，保持仿真停止。
2. 用 `OptUSBProj-yolo` 环境启动原人体 GUI；该环境已安装 ZeroMQ Remote API 客户端。
3. 分配设备，选择姿态模式，并应用穿戴标定。原 IMU/重力/RGB-D 链路不变。
4. 点击主界面的“新机器人双臂实时预览…（CoppeliaSim）”。
5. 在连接前设置端口、肩肘／腕部独立限速、预览角度区间和是否记录日志，再点击“连接 / 重新读取场景”。左右两侧使用同一组限速：关节 1–4 默认 120°/s，关节 5–6 默认 240°/s（可调 5–720°/s）。连接期间锁定设置；需要调整时，关闭并重新打开配置窗口，在连接前修改。这只用于仿真预览，不是真机安全限速。
6. 勾选左臂、右臂或双臂；手掌朝向需要该侧另一台已分配且归零的手背设备。
   任务默认选“肘腕位置＋可选手掌朝向（X1 默认方案）”，默认统一比例。停止后可切换到“骨段向量”模式，对比同样的人体动作；不需重新连接或重新标定。
7. 点击“启动所选手臂跟随”。停止按钮保留当前场景角度，不清零。

窗口顶部提供“打开 CoppeliaSim 环境”和“关闭 CoppeliaSim 环境”。默认启动保存的中立位场景，可选择安装目录及其他 `.ttt` 文件；打开前检查所选端口，已有 API 实例时复用，不替换其当前场景。端口已占用但 API 不响应时不重复启动。启动进程不代表场景加载完成，待窗口加载完毕后仍需点击连接。

“新启动环境使用 NVIDIA GPU 渲染”默认开启，以 `__NV_PRIME_RENDER_OFFLOAD=1`、`__GLX_VENDOR_LIBRARY_NAME=nvidia` 和 Qt XCB 启动，清除继承的软件渲染覆盖项及 Python Qt 插件路径。已有实例不会在线切换 GPU，需关闭后重新打开。此设置加速图形预览，不加速 IK 或自动保存。大场景建议关闭 CoppeliaSim 自动保存，改为手动保存，避免周期性保存阻塞 API。

关闭环境前显示确认提醒，先停止跟随并退出通信工作线程，然后通过所选本机端口调用 `sim.quitSimulator()` 请求正常退出；不自动保存、不强杀进程。若环境繁忙或显示保存/退出弹窗，需要在仿真器中处理。仅关闭配置窗口不会退出 CoppeliaSim。

### 腕部速度诊断记录

连接前勾选“记录角度、腕部目标速度 / 5、6 角速度 / 朝向误差及时序”，开启需要测试侧的手掌朝向，复现后停止跟随。日志位于 `OptUSBProj-ubuntu/recordings/coppeliasim/*.jsonl`，成功发布行新增按左右侧分类的 `wrist_diagnostics`，窗口同时显示实时数值。记录不改变目标、权重、限速或发布逻辑。

- `target_speed_deg_s`：映射及固定转向后的目标掌面在机器人底座系下的 SO(3) 最短角增量除以 GUI 输入快照时间差，单位 °/s，非逐轴欧拉角差。它包含手臂整体运动。
- `target_relative_forearm_speed_deg_s`：相对于目标前臂坐标系的掌面角速度大小，臂段朝向约束启用时提供，用于区分整体转臂与屈腕动作。
- `joint5_velocity_deg_s`、`joint6_velocity_deg_s`：相邻成功读回的场景关节角差除以读回时间差，有符号，单位 °/s。这是运动学仿真回读的差分估计，不是真机编码器测速；底层 RPC 内部具体赋值时刻不可见。
- `orientation_error_deg`：目标掌面与实际回读构型 FK 掌面之间的 SO(3) 夹角；还记录误差旋转向量及目标/实际旋转矩阵，便于离线重算。
- `wrist_step_limit_active`、`wrist_joint_limit_active`：分别标记 J5/J6 是否接近本轮增量边界或配置的关节区间边界；还记录本轮 `step_limit_deg` 及六个关节角速度。

独立腕部限速版本中，`step_limit_deg` 保留为肩肘单步上限；新增 `joint_step_limits_deg` 和 `wrist_step_limits_deg` 分别保存六个关节及腕部的上限。日志配置保存 `joint_speed_limits_deg_s`、`joint_step_caps_deg`。每轮增量限制为 `min(速度×循环间隔, 单步上限)`：肩肘单步上限保持 9°，腕部单步上限为 `9°×腕部限速/120°每秒`，避免固定 9° 又将腕部速度卡在约 180°/s（20 Hz）。改为逐关节边界，不改变任务权重、分层锁定或场景关节限位。

首帧、重复输入时间戳、超过 0.5 秒的采样间隔使用 `null` 表示无法可靠差分，不伪装成零速度；暂停、断流等待、停止或通信恢复时清除差分历史。速度标量不能直接与某个单关节速度一一等同，需同时查看手掌误差、腕轴方向、触边标记及已有 GUI/IK/RPC 时序。

单臂可独立验证；未选择侧的手臂不会被写入，手指仅在独立启用手型预览或 IMU 手指输出时写入。显式勾选“允许手动轴映射”可跳过穿戴标定要求，但仍需在线设备与中立位。默认不勾选。

连接不会修改关节角。关闭窗口会停止发送并退出工作线程。已在途的一次 RPC 无法撤回。重新打开窗口再连接可修改通信与限速参数。勿同时运行关节滑杆 demo 或其他关节控制程序。

运行时 ZeroMQ 发送/接收超过 2 s，先暂停发送并作废旧目标，再关闭旧 REQ 连接，最多尝试两次建立新连接。只读核对场景 UID、对象、限位、底座及运动学几何，读回实际角度；不重发超时的角度请求。超时请求可能已经应用。恢复后保留原运动学与标定，必须明确点击启动。核对失败或两次重连超时则停止并提示重新连接。首次连接超时仍需用户重试。网络恢复不等于恢复跟随授权。

## 模型与数学

### 左右手指离散开合

无需启动双臂跟随，也无需上臂／前臂穿戴标定；只需连接场景。连接只读，不自动张手或握拳。

1. 点击“左右手指姿态配置…”，每侧表格显示五条手指链的三个关节，以及当前场景回读角度。名称按 `jointLH11…53` / `jointRH11…53` 的链编号显示，不凭编号推断拇指。
2. 可以逐项输入张开／闭合角度，或把场景中已摆好的手型读取为对应端点。先确认张开端点，再配置舒适闭合端点；每次编辑撤销该侧两组端点的确认及输出授权。可先确认一个端点并显式预览；IMU 控制要求两组端点均已确认。
3. “预览张开／闭合”平滑移动十五关节；“停止所有手指输出”保持当前位置。两侧分别设置过渡速度，默认 120°/s，可调 5–720°/s，不使用肩肘或腕部速度设置。
4. 打开原“左右手四 IMU”窗口，按原步骤采集开手／闭合参考。勾选该侧“输出离散开合至 CoppeliaSim 手指”。原 RViz 复选框独立保留；其反向映射仅作用于 RViz，不改变手指的张开／闭合语义。
5. 可保存已确认侧的手型 JSON；加载和左右复制后均需重新确认，不自动运动。加载核对关节路径、十五个角度及当前场景区间。程序不自动保存 `.ttt`。

该场景每侧十五关节均为独立旋转关节，当前区间为 0–90°，但全部 90° 不代表合理握拳或无碰撞。默认闭合端点未确认，不能直接启用；本功能没有接触、力反馈或手指碰撞保护。

双 IMU 仅提供离散状态，`false` 对应张开端点，`true` 对应闭合端点，不复用 X1 夹爪的 0/1 rad 约定。过渡采用一个公共比例：令目标端点为 \(q_*\)，本轮场景回读为 \(q\)，则

\[
q_{\mathrm{next}}=q+\beta(q_*-q),\qquad
\beta=\min\left(1,\frac{v\min(\Delta t,0.1\ \mathrm{s})}{\lVert q_*-q\rVert_\infty}\right).
\]

其中速度 \(v\) 换算为 rad/s；目标已达到时不移动。十五关节沿直线协调过渡，各关节增量不超过速度边界。0.1 秒间隔上限避免长时间通信暂停后一次跳到端点。

手指请求通过 GUI 内部信号传入独立线程安全邮箱，使用两设备同期样本时间而非 GUI 刷新时间；样本年龄超过 300 ms 不继续移动。手势无效／采集中暂停保持；新有效数据可以继续。清除参考、更换设备／阈值、关闭手势窗口、停止输出、编辑手型、重新连接或关闭机器人窗口会撤销授权。通信超时清除所有手指请求，恢复后需明确重新启用，绝不盲目重发。

双臂和手指由同一个 `SceneWorker` 和 `SceneBridge` 批量发布、回读，手指不参与臂部 IK；所选侧手势与手型预览互斥。场景读回确认仅证明运动学赋值成功，不是真机反馈。连接时校验手指父子链、对象 UID、类型、依赖及限位；批量写入前验证全部目标。

启用原记录复选框后，手指发送轮记录 `event: hands`，包含 `hand_angles`、`hand_targets`、`hand_requests`（端点目标、样本时间、速度、输入来源）及回读时间。停止期间不持续记录无写入手指帧；原双臂与腕部日志格式保留。

独立仿真实例的小幅端到端测试：`python demos/test_scene_hand_live.py --port 23001`。必须事先在该端口加载同一场景并停止仿真；测试临时把两侧手指移动至 5°，验证臂角不变及停止保持，最后恢复原手指角度，不保存场景。它使用合成离散指令，不代表已验证真实四 IMU 手势或真实抓取。

对象路径为 `/BaseLinkHull/jointL1…6`、`jointR1…6`，掌部为 `LinkLHMainHull` / `LinkRHMainHull`。连接时核对父子链、关节类型、依赖、场景对象 UID。场景底座移动、对象更换、仿真启动或通信失败会终止发送，需重新连接。

连接时的角度为运动学采样参考 `q_ref`，并非机器人中立位。机器人的中立位固定为两侧 `[0,0,0,-π/2,0,0]`；它是本场景下手臂下垂的参考。全零角实际屈肘约 90°。本版本只针对这份场景，不是任意机器人自动识别器。

从当前关节基座矩阵读取轴方向和位置，以底座系 B 表示：

\[
S_i=\begin{bmatrix}\omega_i\\-\omega_i\times p_i\end{bmatrix},\qquad
T(q)=\prod_{i=1}^{6}\exp([S_i](q_i-q_{\mathrm{ref},i}))M.
\]

掌部子连杆用于工具朝向，工具原点取第六关节中心。肩、肘、腕点取第二、第四、第六关节中心。肩中心随第一关节旋转，所以不能假定肩点固定。

从中立位双肩方向得到左向轴；由上臂下垂方向得到上向轴并正交化，前向轴由叉积得到。形成 GUI 人体系到 B 系的旋转矩阵 `C`。这是本场景装配约定，不是相机标定矩阵。

从 `PoseEngine.transforms(include_natural=False)` 提取人体肩肘腕。人体中立几何来自空 `PoseEngine` 的标准模型，不能以点击启动时的人体姿态代替。

默认使用原 X1 的中立位骨段位移映射，并加入坐标转换 `C`。设上臂、前臂向量为 `a_H=e_H-s_H`、`b_H=w_H-e_H`，中立位向量为 `a_H0,b_H0`，机器人中立点为 `e_B0,w_B0`：

\[
e^*=e_{B0}+s_uC(a_H-a_{H0}),\qquad
w^*=w_{B0}+s_uC(a_H-a_{H0})+s_fC(b_H-b_{H0}).
\]

统一比例时 `s_u=s_f=||w_B0-s_B0||/||w_H0-s_H0||`。分段比例时，分别使用中立位上臂和前臂长度比。位置任务残差为 `r_e=e_B(q)-e*`、`r_w=w_B(q)-w*`，残差权重分别为 2.5 和 5。这与 X1 的位置目标构造一致；不照搬 X1 特定腕轴修正或第四关节趋零惩罚。

备选“骨段向量”模式把人体骨段归一化为 `u_H,f_H`，按机器人骨段长度匹配方向：

\[
r_u=e_B(q)-s_B(q)-l_uCu_H,\qquad
r_f=w_B(q)-e_B(q)-l_fCf_H.
\]

若启用手背，GUI 标准中立位手掌矩阵为单位矩阵，故目标工具朝向为

\[
R^* = C H(t) C^\mathsf T R_{\mathrm{tool}}(q_N),\quad
r_R=\operatorname{Log}(R^{*\mathsf T}R_{\mathrm{tool}}(q))^\vee.
\]

此处故意不使用仅用于人体显示的自然掌面偏置。位置模式的腕/肘残差权重为 `5/2.5`；向量模式的两个骨段残差权重均为 `5`。共用连续性 `0.06`、中立位 `0.008`、可选掌面 `0.3`。无手背时，腕部两关节增加 `0.04` 中立偏置。这些是残差权重，目标函数使用其平方。

左右手分别提供“手掌目标固定转向（实验）”，默认关闭；可选择机器人中立手掌局部 `x/y/z` 轴，角度范围 ±180°，有 ±90° 快捷按钮。只有该侧手掌朝向任务开启、有手背输入时生效，停止跟随后方可调整。不修改 STL、人体标定或直接给关节角加偏置。

显式使用人体标准手掌中立矩阵 `H_0` 后，偏置目标为

\[
R^*=C H(t)H_0^{\mathsf T}C^{\mathsf T}R_{\mathrm{tool}}(q_N)K,
\qquad K=\exp([\hat a]_{\times}\beta).
\]

误差仍为 `Log(R*ᵀ R_tool(q))`，原掌面残差权重不变。右乘 `K` 表示固定目标掌面偏置，**会改变中立位目标**，不等于保持中立位的腕部解剖轴重映射。轴不是人体轴，也不能仅靠截图确定；逐侧、小角度检查正负方向和可达性，尤其避免拇指碰身体。本版无碰撞保护，无法保证每种腕部动作同类复现。偏置配置写入每条发送日志的 `palm_offsets`，关闭后恢复原目标。

两种模式使用同一个有界求解器、连续性和中立位项、手掌朝向项、限速与限位。切换任务不改变人体标定。使用 SciPy 有界最小二乘，上一发送/读回角为初值，每次最多 25 次函数评估。目标不可达时允许有界渐进的折中解，显示残余误差，不宣称精确还原。暂未提供独立“精确末端位姿优先”模式。

### 默认分层关节任务分配

窗口新增“关节任务分配”，默认“臂段 1–4 → 手腕 5–6”；原六关节联合优化保留为对照。停止跟随后可切换，两种肘腕任务均支持。

第一阶段固定当前关节 5–6，只优化 1–4：位置/骨段残差、上臂/前臂朝向残差、连续性和中立偏置沿用原定义，**不加入手掌朝向残差**。第二阶段严格固定第一阶段的 1–4，只优化 5–6，加入原手掌残差；同时保留原位置项，以处理腕部机构偏置可能导致的腕点变化。不开手掌时第二阶段仅采用原臂段任务和腕部中立偏置。每阶段最多 25 次函数评估，并各自检查有限、有界及不增大该阶段目标，不要求分层解比全局联合目标更小。

可写为

\[
q_A^*=\arg\min_{q_{1:4}} E_{\mathrm{arm}}(q_{1:4},q_{5:6}^{\mathrm{prev}}),
\quad q_W^*=\arg\min_{q_{5:6}}\left[E_{\mathrm{arm}}(q_A^*,q_{5:6})+
\|0.3r_{\mathrm{palm}}(q_A^*,q_{5:6})\|^2\right].
\]

因此改变手掌目标不能改变本轮第一阶段结果，不会为了改善掌面残差借用肩部。臂段输入发生变化仍会驱动肩肘；腕部机构偏置也可能使后续位置任务需要调整，不能承诺实际输入中肩部永远不动。两个腕自由度不保证任意 SO(3) 目标可达，固定 90° 目标偏置同样可能不可达。界面显示掌面残差，超过 5° 时提示“腕部目标未完全达到（不借肩部代偿）”；该数值是提示阈值，不阻止更新。日志保存 `solver_mode`。

实际导出几何的纯腕目标离线对照：原联合方案关节 2 峰值偏转约 1.12°，默认分层方案为 0°，最终掌面误差均约 0.047°。这只是同一可达目标的实验，不是所有真人动作的保证。

### 可选臂段朝向软约束

“臂段朝向软约束”默认开启，残差权重默认 `0.15`，范围 `0…1`。停止跟随后可关闭复选框，或设权重为 `0`，恢复原纯位置/骨段向量任务（仍保留原连续性等项及可选手掌任务）。这个权重与穿戴标定的弱先验 `lambda` 无关，数值相同只是初始设置。

只约束肩、肘、腕位置时，伸直臂绕长轴转动几乎不改变这些点的位置，因此第三关节可能走到不希望的旋转分支。现在同时使用 GUI 上臂、前臂完整旋转；不要求手背设备。对每个臂段 `s`，设人体旋转为 `H_s(t)`，标准人体中立旋转为 `H_s0`，机器人中立臂段旋转为 `R_s(q_N)`：

\[
R_s^*(t)=C H_s(t)H_{s0}^{\mathsf T}C^{\mathsf T}R_s(q_N),\qquad
r_s(q)=\operatorname{Log}\!\left(R_s^{*\mathsf T}R_s(q)\right)^\vee.
\]

将两个残差 `w_s r_s` 拼入原最小二乘残差，即目标函数增加

\[
w_s^2\left(\|r_{\mathrm{upper}}\|^2+\|r_{\mathrm{fore}}\|^2\right).
\]

这样复制的是相对于中立位的空间旋转，而不是要求机器人掌面与人体掌面绝对同向。机器人可保留避免拇指碰身体的中立构型。中立仍按上述固定 `q_N` 定义；保存场景不等于任意当前关节角自动成为中立位。

实现采用固连于上臂的第四关节基座作为上臂虚拟坐标系（包含第三关节转动，不包含第四关节转动），第五关节基座作为前臂虚拟坐标系（包含第四关节转动，不包含第五关节转动）。连接时从场景提取这些矩阵，不手工猜测 CAD 轴。

朝向与位置是软性联合拟合；人体和机器人结构不同，不能保证所有任务同时零误差。GUI 与日志分别显示上臂、前臂朝向误差（度）。不开手背时，独立腕关节运动仍无观测，只受原中立偏置等项约束。RGB-D 骨段方向不能直接观测长轴扭转，因此臂段朝向仍可能受该方向 IMU 漂移影响；此功能不是防碰撞或真机安全保证。

## 行为、诊断与限制

- 默认限速 120°/s、单步上限 9°，直接复用 X1 的常量。按真实周期计算，不再额外将周期截断为 0.1 s；低速仍可在连接前配置。单步上限保留的是与 X1 相同的长卡顿单帧保护，而非原先额外的 6° 限制。
- 默认只使用场景关节区间，额外 ±150° 区间默认关闭，可显式开启。**场景区间不是已验证的机械安全限位，无碰撞保护，不用于真机。**
- GUI 50 ms 采样，工作线程按 50 ms 目标周期补足等待；若求解＋RPC 已超过周期，不再额外等待 50 ms。不保证稳定 20 Hz，总频率取决于计算和通信耗时。残差计算复用同一条 PoE 前缀链，未改变任务权重或目标函数。
- 连接期间调用 CoppeliaSim 自带 `sim.fastIdleLoop` 加快停止仿真状态的 RPC 调度；正常关闭时恢复。应用级标记避免超时重连重复递增快速空闲引用计数。若程序异常退出/服务器无法访问，恢复只能尽力完成，下一次连接沿用标记，关闭时释放；必要时重启 CoppeliaSim。此优化可能增加仿真器 CPU 占用，不启动仿真、不保存场景。
- 所选 IMU 数据年龄超过 0.25 s 时作废待发送目标并保持当前机器人角度，GUI 继续检查输入。如果所有所选设备恢复到 0.25 s 内、且分配/姿态模式/映射/标定参考与启动时一致，则自动按原限速继续，不回放积压目标。任何所选设备年龄达到 1 s 则停止本轮，必须明确点击启动。负时间异常、其他输入错误、标定变化及通信超时仍停止，不自动恢复。1 s 按设备数据年龄计算，不是从发现超时再等待 1 s。暂停中不发送旧姿态，也不提高限速追赶。
- 日志位于 `OptUSBProj-ubuntu/recordings/coppeliasim/*.jsonl`，含场景配置、任务模式/长度比例、目标/读回角、输入时间、误差、超时与恢复事件及工作线程失败原因。
- 复现断续跟随前，请在连接前勾选“记录角度、超时原因及 GUI / IK / 通信耗时”。窗口独立的“时序诊断”区分 `IMU 数据不新鲜`（部位、设备 ID、数据年龄）、`GUI 快照超时`、`求解快照过期`、授权改变及主动停止。发送记录的 `timing` 包含 GUI 采样间隔、采样时各 IMU 年龄、左右 IK 耗时、求解快照/最新快照年龄及 RPC 耗时；未发送轮次也记录原因事件（同类事件最多每 0.5 s 一条）。收包诊断新增 `follow_input_waiting`、`follow_input_resumed`，分别记录短暂断流等待和自动恢复；持续断流/其他输入错误记录 `follow_input_rejected`。250 ms 旧数据门槛不变，恢复授权按上一条规则处理。
- “导出本次运动学配置”保存诊断 JSON；目前不作为跨场景配置导入功能。
- 不启动仿真、不修改关节动态模式、不保存原 `.ttt`、不经过 ROS、不改 X1 链路、不控制真实电机。手指仅通过明确启用的手型预览或离散开合通道控制。

## 验证

进一步定位 IMU 断流时，连接前勾选日志，程序自动生成同名 `*.ingress.jsonl`。此日志持续到预览窗口关闭/重新连接，即使跟随因超时停止也继续记录。包括 UDP 轮询间隔、读取耗时、每个来源端点的数据报间隔/字节数、解析成功包数/丢弃字节/残留缓冲、每台 IMU 的解析包间隔、设备时间与 RSSI、主 GUI 收包回调整体耗时以及输入拒绝时各设备年龄。无需另开 UDP 1399 监听器，不记录原始图像或 UDP 负载。记录的是应用 `recvfrom` 时间，不能单独证明内核到达间隔；严格区分网络与应用调度仍可能需要系统抓包。诊断缓存有界，溢出会显式记录，避免把日志丢失误判为网络丢包。关闭日志时不积累诊断事件。

离线测试覆盖点雅可比差分、有界跟随、停止消息失效、设备/标定/数据新鲜度门槛及非法角度拒绝。显式现场测试命令：

```bash
cd /home/hzb/Work/WT901
conda run --no-capture-output -n OptUSBProj-yolo python demos/test_scene_robot_live.py --live --gui
```

`--live` 临时移动双臂少量角度，最终恢复十二个原始角度，检查三十个手指角不变。`--gui` 无头连接独立窗口，检查默认不发送和缺设备不启动。二者不是实际人体遥操作体验、动力学或真机安全验证。

另有 `--follow` 合成输入测试：通过真实 GUI 采样、工作线程 IK 和 RPC 使右臂运动，检查未选择的左臂保持不动，以及源超时后停止发送，最后恢复双臂原角度。2026-10-10 已通过上述现场检查、新模块 5 项离线测试和原 X1 的 35 项 IK/随动回归测试。实际人体佩戴后的效果仍需用户验收。

同日更新后，新模块离线测试增至 10 项，包含与原 X1 位置映射的数值一致性、有界位置 IK、通信暂停授权、场景身份变化拒绝和“写入已应用但回复丢失”的超时恢复测试。`--follow` 会分别验证默认位置模式与备选向量模式。两种模式均已通过现场合成输入检查；通信故障恢复采用可重复的模拟故障注入验证。

加入臂段朝向后离线测试增至 14 项，新增虚拟臂段坐标系的关节作用范围、伸直位扭转歧义消除、零权重与旧任务逐项一致、中立旋转映射检查。开启朝向约束的两种任务也通过真实 CoppeliaSim 合成输入检查，测试后恢复双臂原角度。这不替代实际人体佩戴测试。

发布节奏优化后的现场合成测试（2026-10-10）：位置/向量任务发布间隔中位数分别约 48.7/47.9 ms，RPC 中位耗时约 2.3/2.8 ms；默认限速 120°/s。两种任务均验证短暂断流保持、数据恢复后自动继续和持续断流停止，最终恢复双臂角度。该计时是短时合成输入测试，不代表复杂双臂真人输入始终达到相同频率。
