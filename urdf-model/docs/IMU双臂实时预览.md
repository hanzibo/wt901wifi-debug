# WT901 → X1 双臂实时 RViz 预览

这是离线双臂回放通过人工验收后的下一阶段。它复用现有人体 STL 主窗口的 WT901 接收、设备分配、穿戴标定和归零状态；**只向 RViz 发布 `/joint_states`，不访问实体机器人或控制器**。同一时刻只能有一个持续关节状态发布者，勿同时开启旧的 X1 滑块面板、离线回放或卖家关节 GUI。

## 启动顺序

1. 打开原有人体 STL 主界面：

   ```bash
   cd /home/hzb/Work/WT901
   conda run --no-capture-output -n OptUSBProj-fusion \
     python -u OptUSBProj-ubuntu/run.py
   ```

2. 点击“X1 双臂实时预览…（RViz）”，再点“启动 RViz 模型”。GUI 会运行 `display.launch.py use_gui:=false`，打开机器人模型；请勿与手动启动的同一 launch 并行。
3. 在主界面将四台设备分别分配给左/右上臂和前臂，完成**本次穿戴标定并应用结果**。摆好中立位后再归零，在 X1 弹窗点击“开始 RViz 随动”。GUI 会自动在 `x1_ros2_py` 环境启动本机 ROS 接收进程，不再需要另开终端。

### 可选：左右手掌朝向跟随

四台臂段设备仍按上述流程标定。另将设备分配给左手和/或右手，使用符合实际绑法的手动轴映射，或应用该手通过验收的整臂平举标定。手腕伸直、摆出中立姿势，并让手与前臂的中立参考一致；在 X1 弹窗分别勾选“左手掌朝向跟随”和“右手掌朝向跟随”，启动预览。支持只启用一侧，也可同时启用两侧；两侧手背须使用不同设备。不勾选时沿用双臂位置随动。启动后若改动映射、姿态算法、标定或归零，当前预览会停止，须重新启动。

右手复用左手的前臂相对手掌旋转与软约束求解，按镜像轴向处理：模型 +Z 长轴转动对应关节 55，拇指侧偏 +X 对应关节 56；左侧仍是关节 5 和 6（拇指侧偏 −X）。两侧长轴关节的预览范围扩大为 ±90°，侧偏保持 ±45°；若 URDF 有更严格数值限位则遵守该限位。朝向是软约束，所以允许角度范围不等于严格等幅跟随；这也不是实机安全限位。

注意：两侧关节角的符号不相同。URDF 中立位下，关节 5 的正轴朝世界 +Z，而关节 55 的正轴朝世界 −Z。因此同样的模型 +Z 长轴正转，左侧对应关节 5 正转，右侧对应关节 55 负转。这是为保持实际空间旋转方向一致，不是右手 IMU 数据取反；手掌标定和侧偏映射不变。

侧偏方向另行处理：关节 6 与 56 的正轴在中立位均朝世界 −X。左手拇指侧偏为模型 −X，对应关节 6 正转；右手拇指侧偏为模型 +X，对应关节 56 **负转**。两侧模型 +X 均映射到空间 +X，不能仅因左右拇指方向不同而把右手 +X 映射到关节 56 正转。此修正作用于两个动作模仿后端；完整末端位姿后端的世界朝向目标保持不变。长轴、限位和手动/标定映射均不改变。

此原型使用**手相对前臂**的旋转。经 URDF 正运动学核对，X1 左腕关节 `5` 的转轴在零位几乎与前臂长轴重合；现将模型长轴 `+Z` 对准关节 `5`，拇指侧偏 `−X` 对准关节 `6`。掌屈 `+Y` 是剩余的第三个独立方向，不能由这两个腕关节在维持前臂姿态时完整复现；该分量会体现在弹窗显示的朝向误差中，不强迫肘部追随。朝向仍是软约束，肘/腕位置和动作连续性优先。手背短时断流时保持机器人的当前腕部朝向，双臂位置仍可随动；四台臂段设备的原有断流保护不变。手背为 6 轴算法时，航向可能漂移，建议先做短时的长轴转动和侧偏对照，不把朝向误差当作真机控制精度。

“停止”只停止随动及本窗口启动的 ROS 接收进程，RViz 模型可留着重新标定；“关闭 RViz 模型”才会结束该弹窗启动的 RViz/robot_state_publisher。关闭 X1 弹窗只是隐藏控制窗口，随动、诊断录制和 RViz 均继续运行；主界面的 X1 按钮会提示“后台随动”，可随时重新打开弹窗操作。退出整个人体模型程序时，才会清理它启动的接收进程与 RViz。若模型原本由外部终端启动，弹窗不会关闭它。

当前人体主窗口独占 WT901 UDP 1399；X1 弹窗不另占该端口。主窗口与 ROS 进程通过仅绑定本机 `127.0.0.1:13990` 的预览消息通信，便于两个现有 Conda 环境继续分离。点击“停止”、退出主程序或 ROS 进程断开才会停止新的关节状态发布；RViz 可能保留最后一帧，这并不代表设备仍在线。

## 同步诊断记录

每次点击“开始 RViz 随动”都会自动创建一个目录：`OptUSBProj-ubuntu/recordings/x1_live/日期时间-编号/`，停止预览后弹窗显示完整保存路径。该目录包含：

- `frames.csv`：每次实时 IK 更新占一行，使用同一个电脑单调时钟时间戳。保存四台臂段 IMU（启用时再加对应手背）的最近姿态、角速度、接收时间和包计数，以及同一帧的人体肩/肘/腕位置、机器人肘/腕目标与实际位置、候选解、最终发送的十二个关节角、IK 误差、断流状态、ROS 接收应答序号和帧间隔。分别记录两侧手背状态、长轴相对角、目标/实际前臂相对腕部旋转向量及朝向误差。
- `manifest.json`：四台设备的 ID、当次应用的轴映射与中立位矩阵、URDF 文件指纹、录制起止时间及终止原因。

这份数据是**每个求解时刻的同步快照**，并非 50 Hz 原始 WT 包的无损录制；设备包计数和接收时间可识别某帧是否复用了旧数据。ROS 应答代表接收进程收到预览帧，不代表 RViz 已绘制该帧。复现肘部快速转动后，停止预览并提供该目录即可对比“传感器与目标点是否先跳动”及“目标平稳但关节角是否加速”。目录属于本机录制，Git 默认忽略；分享时请留意其中包含设备 ID 和动作数据。

## 数据与保护边界

- 与离线版本共用 STL 中立骨段、目标点缩放、双臂 URDF 正运动学和逐帧 IK；默认位置模式仍让机器人手腕接近中立。勾选对应手掌模式后才纳入该侧手背相对朝向；躯干仍未检测。
- 开始前要求四台不同设备数据新鲜，且四处都已应用连续穿戴标定。归零、改绑、改轴映射、重新标定或设备参数改变后，当前预览自动停止，须重新检查并启动。
- 某侧短时断流或 IK 拟合失败，只保持该侧最近姿态；断流超过约 1 秒则停止两侧的预览发送。本机 ROS 进程在没有新帧约 0.3 秒后停止发布。
- 弹窗显示每侧数据延迟、跟随/保持状态，以及 ROS 接收进程是否回应；启动后约 8 秒仍没有应答会自动停止，运行期间应答中断约 2 秒则停止。

这里的 IK 角度范围、120°/秒的按时限速与 9° 单步限制只为 RViz 预览设计，**不是 X1 真机的可靠机械限位或速度约束**。当前没有碰撞/环境约束、执行器反馈或急停，因此不得把该消息链路接至真机控制接口。
