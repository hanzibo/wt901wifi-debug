## 环境与启动顺序

已验证的本机环境：Ubuntu 26.04、GNOME Wayland、ROS 2 Lyrical；Conda 环境 `x1_ros2_py` 使用 Python 3.14，并可导入 PySide6、`rclpy`、`sensor_msgs` 等依赖。每个终端都要先加载 ROS，再加载本工作区；运行 Python 面板的终端应先激活 Conda，随后加载 ROS 与工作区。

首次使用或修改描述包后构建：

```bash
cd /home/hzb/Work/urdf-model
source /opt/ros/lyrical/setup.bash
colcon build --packages-select pkg_robot_model
```

终端 1：

```bash
cd /home/hzb/Work/urdf-model
source /opt/ros/lyrical/setup.bash
source install/setup.bash
ros2 launch pkg_robot_model display.launch.py use_gui:=false
```

终端 2：

```bash
cd /home/hzb/Work/urdf-model
source ~/miniconda3/etc/profile.d/conda.sh
conda activate x1_ros2_py
source /opt/ros/lyrical/setup.bash
source install/setup.bash
python script_python/check_environment.py
python script_python/x1_joint_qt.py
```

不要在已有 RViz 实例上反复启动同一 launch：多个 `robot_state_publisher` 或多个关节发布器会让调试结果难以判断。改完 launch/RViz 配置后，先退出旧实例，再构建并重新启动。当前建议仅构建 `pkg_robot_model`；其余卖家包还没有在 Lyrical 上完整适配。

## 控制链路如何工作

1. `display.launch.py` 启动 `robot_state_publisher` 和 RViz，加载 `pkg_robot_model.urdf` 与 `display.rviz`。
2. `use_gui:=false` 关闭卖家的 `joint_state_publisher_gui`。一次性脚本 `seed_joint_state.py` 等待 ROS 订阅就绪，发布 16 个关节的零位姿态后退出，所以 RViz 在 Qt 面板打开前也可显示完整模型。
3. `x1_joint_qt.py` 用滑块或角度输入修改姿态，约每 33 毫秒向 `/joint_states` 发布一次 `sensor_msgs/msg/JointState`。界面以度显示，发布前换算为弧度。
4. `robot_state_publisher` 根据 URDF 和关节状态发布 `/tf`、`/tf_static`，RViz 的 RobotModel 据此更新每个网格的位置。

主要代码入口：

| 文件 | 修改它的场景 |
| --- | --- |
| `pkg_robot_model/urdf/pkg_robot_model.urdf` | 修改机器人几何、关节或坐标系 |
| `pkg_robot_model/config/display.rviz` | 修改视角、显示组件或目标帧率 |
| `pkg_robot_model/launch/display.launch.py` | 修改 RViz/ROS 节点启动方式和 Wayland 兼容设置 |
| `pkg_robot_model/scripts/seed_joint_state.py` | 修改启动时零位姿态发布逻辑 |
| `script_python/x1_common.py` | 修改 16 个关节的名称、标签、可视范围和预设姿态 |
| `script_python/x1_joint_qt.py` | 修改 Qt 界面、用户交互和持续发布逻辑 |
| `script_python/x1_motion_demo.py` | 无界面动作演示 |

`script_python/x1_joint_gui.py` 是保留的 Tk 旧版面板；新开发以 Qt 版为准。

## 快速检查

```bash
ros2 node list
ros2 topic info /joint_states --verbose
ros2 topic echo /joint_states --once
ros2 run tf2_ros tf2_echo world base_link_0
```

Qt 面板运行期间，`/joint_states` 应有一个持续发布者 `x1_python_joint_qt`，`robot_state_publisher` 是订阅者。若模型在两个姿态间跳动，检查是否同时启动了卖家的 GUI、旧 Tk 面板或第二个 Qt 面板。`check_environment.py` 负责检查 Conda、ROS Python 与 Qt 模块是否能在当前终端导入。

## 范围与下一步

当前 Qt 面板直接发布关节状态，因此适合 URDF、TF、动作与界面开发。它没有控制器反馈、碰撞、重力、速度约束或真实执行器。要做动力学仿真，需要把 Gazebo Classic 文件迁移到当前的 `ros_gz_sim`/`gz_ros2_control`；要做规划，需要完成 MoveIt 依赖及控制器集成；要做真机控制，需要先移植 `xiaobei_hardware`，再确认关节 ID、零点、方向、限位和急停。

Wayland 闪烁、模型不可见、字体与帧率的排查过程记录在 [环境审查与 RViz 排障指南](环境审查与RViz排障指南.md)。Conda 环境定义和更多控制命令见 [Python 控制说明](../script_python/README.md)。
