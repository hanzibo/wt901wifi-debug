# 五指机器人手动串口 Demo（Ubuntu）

独立示例，不导入或修改 `OptUSBProj`，不改变 IMU／RGB-D／仿真链路。
协议来自原始 PC 发送代码，基本手动控制已由用户验证；新电位器五指链路仍须逐指真机验收。

## A4 单电位器控制指定手指

使用原来的桌面启动项即可，无新增依赖。在窗口中向下滚动可见「A4 单电位器 → 指定一根手指」。
启动不打开 Nano 或机器人串口。Nano 只读采集，机器人仍由原来的唯一发送线程写入完整54字节帧。
兼容当前已烧录的 POT5 固件，无须重烧：固件仍发送五路字段，但电脑只提取 A4，完全忽略 A0–A3。
断开的 A0–A3 浮空数据不会参与目标计算，也不需要对它们标定。这里只改电脑程序，不改开发板固件。

1. 关闭独占 Nano 串口的「五指电位器实时数据」监视器。选择 Nano CH340（默认稳定 by-id 路径），点击「连接 Nano（只读）」。不要选机器人 CP2102；两个串口不能混用。
2. 先不连接机器人，检查 A4 当前 ADC 是否正确。选择左／右手及「协议指1…5」。物理指序尚须逐指核对，不能仅凭 RH1/LH1 名字认定拇指。
3. 将 A4 电位器置于张开参考，点击「采集当前为张开」；再置于闭合参考并采集。也可输入端点。ADC 端点须至少相差20，允许闭合值小于张开值，即反向映射。
4. 设置所选手指的「输出开／输出闭」，观察右列目标量。默认0…200只是小范围调试起始值，不是已验证安全区间，更不是角度。映射按两端线性插值并裁剪；不估计各指关节角。
5. 可保存／加载版本2的 A4 JSON 标定（包含侧别、目标指及端点）。加载时输出许可重置为关闭；旧五路配置不会自动迁移，请重新采集。
6. 勾选「许可所选指」。连接机器人 **CP2102**，人工确认机器人确实处于已验证上电姿态（角90°／指量0），设置手指速度、加速度与发送频率，完成上方安全确认及解锁。逐轴滑杆实时模式须关闭。
7. 点击「明确启动 A4 → 所选指」并确认弹窗。首帧保持确认起点，之后限速／限加速度跟随最新目标。其他15个角及其余9根手指均冻结于最后确认／写出指令，不使用尚未发送的界面滑杆目标。运行中不能切换手／指，须先停止并等待实际稳定。
8. 点击「减速停止」可完成指令侧制动，保留最后写出目标作为估计起点；需等待实际稳定，再解锁启动。输入超过500ms未更新、Nano重启或序号／时钟回退亦减速停止，数据恢复不会自动重新启动。软件停止不是物理急停。

采集50Hz不强制发送50Hz，发送沿用窗口设置（默认50Hz）。最新目标覆盖旧目标，不建立待执行队列。
规划使用协议控制量单位：默认200单位/s、400单位/s²，不是物理角速度／角加速度。
当前算法对量化前轨迹施加约束；整数控制量仍有小台阶。厂商黑盒或串口缓存内的延迟无法由此消除。
收包时间结合 Nano uptime 判断，避免短暂界面卡顿把积压包误认为新数据；发送线程另有独立超时检查。
无法检测物理碰撞、机械极限或实际手指位置。

连接机器人前勾选原「记录串口发送诊断」可记录 `pot_input`（仅A4 ADC、序号、uptime、时间及丢序计数）、
`pot_mapping`（侧别和映射端点）、`live_target`（最新目标与有效期）、`write`（实际写出帧）及停止原因。
未连接机器人或未启用记录时仅界面预览，不单独落盘。

## 默认行为与控件

- 启动不枚举、不打开串口、不发送任何命令。
- 双臂十二轴、H1/H2/腰部三轴，使用协议目标角（度）。
- 双手十个手指控制量，范围 0–4095；不是十个关节角度。
- 双臂范围来自师兄旧测试窗口，不代表已验证的当前真机限位。
- 头部／腰部范围 0–327.67° 仅用于防止 int16 溢出，不是机械许可范围。
- 默认臂／头／腰为 90°，手指为 0；这不是当前位置，也不保证安全。
- 默认修改滑杆／数字框仅更新预览；一次轨迹执行中修改会撤销发送并使起点失效。另有显式启用的逐轴实时模式，见下文。
- 默认采用平滑执行，不再通过界面直接跳变发送最终目标。
- 每帧控制全部 25 个通道，没有单轴掩码。即使只改一轴，其他通道也会收到目标。
- 两字节角度明确小端；角度按 0.01°四舍五入，避免旧浮点截断少一单位。
- 校验和、手指打包和 54 字节长度与旧协议一致；不追加换行。

## 开发期间不要接机器人

USB 不需要插入也能完成干运行。先检查滑杆、目标预览与 HEX 编码。
端口识别可以在 demo 未运行时使用下面命令；它们不打开串口或发送运动帧。
USB 供电和接地本身仍有电气影响；确认转接头与机器人电平兼容后再连接。

```bash
lsusb
ls -l /dev/serial/by-id/
```

CP2102 常见设备节点为 `/dev/ttyUSB0`，但不要硬编码：

```bash
udevadm info --query=property --name=/dev/ttyUSB0
```

若节点不是 ttyUSB0，请替换成 by-id 列表对应的实际节点。
把识别输出发给开发者，然后断开 USB 即可；不能由 USB 枚举确认机器人固件协议。
不要使用 `screen`、串口终端、旧机器人程序或发送脚本来“试一下”。

## 只有明确批准的真机测试才使用以下流程

1. 确认 TTL 电平、原接线和机器人稳定支撑。
2. 确认物理急停／断能措施及人员安全距离。
3. 核对所有通道的目标，尤其未控制侧、头部、腰部。
4. 选择正确端口，点击连接；连接提示默认选择否。
5. 连接只打开 115200、8N1 串口，不发送控制帧。
6. 仅在机器人刚上电并静止于默认构型时，点击「确认刚上电默认姿态」。不发送，建立十五角90°、十指量0的起点。用户已实机确认该上电构型；程序不能检测它。
7. 设置小幅目标及速度／加速度，勾选全通道核对确认，再解锁一次平滑执行。
8. 点击平滑执行并确认；全部轨迹写出后自动撤销权限。等待机器人实际稳定后再执行下一次。
9. 修改任意目标后重新核对；修改本身不会发指令。

## 平滑轨迹及中断规则

### 逐轴滑杆实时控制（可选）

桌面原 `Real-Robot-Manual.desktop` 指向本程序，重启 demo 即可使用，无需改启动器。
默认关闭；连接、勾选该模式或移动滑杆本身均不会授权运动。

1. 连接前可勾选日志；连接后，仅在确实刚上电默认构型时确认起点。
2. 勾选「逐轴滑杆实时控制」，选择一个角度通道（双臂、头或腰）。本模式不开放手指量。
3. 设置软件测试区间及原有频率、速度、加速度。选择轴时区间初始化为90°附近±5°，并裁剪到旧软件范围；旧范围不代表机械限位。
4. 核对安全条件，勾选确认、解锁，再点击「明确启动逐轴实时控制」并确认弹窗。
5. 界面同步到最后确认的指令起点，首帧也保持该起点；只有所选轴的滑杆／数字框可操作。未发送的其他界面目标不会写入机器人。
6. 拖动所选轴即可更新目标，超出本次区间会裁剪。后台按所设频率生成限速、限加速度指令，目标邮箱只保留最新值，不排队执行旧滑杆目标。
7. 「撤销发送权限」停止后续写入；断连、关闭、通信错误同样取消。已发指令无法收回，不保证物理制动。取消后起点失效，不能把中途姿态假称为刚上电默认姿态；须安全恢复已确认起点再测试。

默认仍为50Hz、10°/s、20°/s²，可在启动前设置，实时运行中不允许修改。
其他24个通道保持最后确认起点的指令值，但协议仍然发送54字节完整帧。
Ruckig 在线轨迹只约束量化前的命令，不代表实际电机速度、加速度或位置。

**本功能不是机械限位测量工具。** TXD/GND 无位置、电流或接触反馈，无法判别碰撞、堵转或触及限位。
不要靠顶撞硬限位来找上下限；优先向厂商获取资料，并在有独立断能手段、人员避开运动范围的条件下小幅观察。
记录下来的是“人工观察的可用指令区间”，不是认证的物理极限；自碰撞可用范围也会随其他轴姿态改变。
正式程序应保留余量，不能把探索端点直接当作全局安全限位。
手动调试宜低速并采用适当防护，参见 [OSHA 机器人系统安全说明](https://www.osha.gov/otm/section-4-safety-hazards/chapter-4)。软件复选框不是安全认证的使能装置。

### 原一次执行模式

所有通道使用同一个五次时间曲线 `10s³−15s⁴+6s⁵`，起止速度和加速度为零。
按照变化最大的通道及设置的速度、加速度确定总时长，各通道同步结束。
默认角速度10°/s、角加速度20°/s²，手指速度200单位/s、加速度400单位/s²。
这些是调试起始值，不是已验证的真机安全上限。手指单位不是角度。
发送频率可设置1～100Hz，默认50Hz。串口线程按照所选周期逐帧写出，通信卡顿只延长过程，不跳过中间帧或密集补发追赶；实际频率受调度和写入耗时影响，需以日志核对。
改变频率会重新计算采样步数，不按旧步数拉长运动。为保持速度／加速度约束，计划时长向上取整到完整周期，额外时长不足一个周期。
降低频率会增大单帧角度变化，不保证更安全。先在小角度、单关节条件下比较50Hz、25Hz、10Hz；起终角和速度／加速度保持相同。
修改频率同修改目标一样撤销权限，执行中修改会中止轨迹并使起点失效。
角度0.01°、手指整数的量化会产生小台阶；速度／加速度约束针对量化前的命令轨迹，不能保证真实电机动力学。

首次起点需要人工确认；完整执行后使用最后写出目标作为后续起点估计，并非反馈。
执行期间撤销权限、修改目标／速率、断连、关闭窗口或通信异常都会中止轨迹并使起点失效。
中止不发送保持／制动帧，不保证电机立刻停下。不要在中途位置假称「刚上电默认姿态」；
须按机器人的安全流程恢复到已确认默认姿态后才能重新建立起点。
不要在运动尚未实际完成时接着执行下一条轨迹，也不要在外力移动或机器人重启后继续沿用估计起点。

尚未验证初始角度时，不应发送默认帧；程序不能靠未连接的 RXD 自动获取保持目标。
停止发送／断开不发送归零、制动或断能命令，不是物理急停。
串口打开前设置 DTR/RTS 为 false，但无法保证 USB 芯片／驱动没有电平瞬变。
没有自动连接、自动归零、未经确认的周期发送、自动重连或失败重试。
串口线程独占 IO；待执行邮箱最多一个任务，轨迹按需生成，不积压整条帧队列；写超时0.2秒。
已进入系统／USB 的字节不可通过撤销权限收回。
RXD 未接时没有反馈；“已写入”不代表机器人接收、执行或到位。

## 发送诊断记录

连接前勾选「记录串口发送诊断」，然后连接、确认上电起点，再进行小角度复现。
已连接时不能切换记录状态；需要断开后重新连接。勾选记录不会打开串口或授权运动。
每次连接独立创建：
`OptUSBProj-ubuntu/recordings/real_robot_manual/日期时间-随机标识/commands.jsonl`。
窗口显示完整路径，断开或关闭窗口后再提供文件进行分析。

日志字段包括：

- `session_start`：格式版本、端口及关节／手指名称顺序。
- `origin_confirmed`：人工确认的起点；`motion_start`：起点、目标、速度／加速度设置、发送频率Hz、周期、计划步数和时长。
- `write`：实际串口线程调用的单调时钟起止时刻、相邻调用间隔ms、写入耗时ms、完整目标、相邻角度／手指增量、命令变化速度、HEX帧及返回字节数。
- `out_waiting_bytes`：驱动支持时的输出队列观察值，可能为null；即使为0也不证明机器人已执行。
- `motion_complete`、`motion_cancelled`、`serial_error`、`serial_close`：轨迹结束／中断／通信错误及连接生命周期。
- 实时模式另有 `live_start`（轴编号、软件区间）和 `live_target`（最新目标）；`motion_start` 的 `steps`、`duration_s` 为null，表示持续随动。日志不含机械限位或实际到位证据。

`command_velocity_deg_s` 是目标增量除以实际发送间隔，不是测得的机器人角速度。
首帧增量相对于已确认起点；若连续执行，首帧发送间隔包含两次执行之间的等待时间，不能据此推断轨迹瞬时速度。
所有写入记录仅证明主机端行为，不能确认USB线上发送时刻、机器人接收时刻或实际姿态。
文件使用独立线程和有界队列写出；记录故障会提示「记录不完整」，不触发额外控制帧。
建议同时拍摄运动过程，注明发生猛动的关节和大致时刻。
